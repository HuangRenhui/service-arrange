## §1 部署拓扑

### 1.1 最小部署（单机）

```
┌────────────────────────────────────────────┐
│  单台服务器                                │
│  ┌──────────┐  ┌──────────┐               │
│  │ Nginx    │  │ 后端     │               │
│  │ :80      │─▶│ :8082    │               │
│  └────┬─────┘  └────┬─────┘               │
│       │             │                     │
│       │    ┌────────┼────────┐            │
│       │    ▼        ▼        ▼            │
│       │  Mongo   RabbitMQ   ZK            │
│       │  :27017  :5672      :2181         │
│  └────┴──────────────────────────┘        │
└────────────────────────────────────────────┘
```

适用：演示、测试、小规模内部使用。

### 1.2 高可用部署

```
              ┌──────────────┐
              │  Nginx / LB  │
              └───────┬──────┘
                      │
        ┌─────────────┴─────────────┐
        ▼                           ▼
┌───────────────┐          ┌───────────────┐
│ 前端静态资源   │          │ 后端实例 × N  │
│ (Nginx 托管)   │          │ :8082         │
└───────────────┘          └───────┬───────┘
                                   │
              ┌────────────────────┼────────────────────┐
              ▼                    ▼                    ▼
      ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
      │ MongoDB 副本集│    │ RabbitMQ 集群 │    │ ZK 集群(3节点)│
      └──────────────┘    └──────────────┘    └──────────────┘
```

> ⚠️ **多后端实例的硬前提**：`TaskProductor.sendTaskRun` / `sendTaskResult` 当前是**本地方法直调**而非 MQ 投递。多实例部署前必须先改造为真正投递，否则任务无法跨节点流转。详见 [项目现状](10-项目现状.md) 缺陷 P2。

## §2 前置准备

### 2.1 软件依赖

| 依赖 | 最低版本 | 用途 | 备注 |
| --- | --- | --- | --- |
| JDK | 8 | 运行后端 | 与编译版本一致 |
| MongoDB | 4.0 | 数据存储 | 生产建议副本集 |
| RabbitMQ | 3.7 | 消息中间件 | 生产建议集群 + 镜像队列 |
| ZooKeeper | 3.4 | 分布式锁 | 生产建议 3 节点 |
| Nginx | 1.18 | 前端托管 + 反向代理 | 可选 |
| Docker | 20.10 | 容器化 | 可选 |

### 2.2 网络与端口

| 端口 | 组件 | 是否对公网开放 |
| --- | --- | --- |
| `80` / `443` | Nginx | ✅ 是 |
| `8082` | 后端 | ❌ 仅内网 |
| `27017` | MongoDB | ❌ 仅内网 |
| `5672` | RabbitMQ | ❌ 仅内网 |
| `15672` | RabbitMQ 管理台 | ❌ 仅内网/跳板 |
| `2181` | ZooKeeper | ❌ 仅内网 |

### 2.3 资源规划（参考）

| 组件 | CPU | 内存 | 磁盘 |
| --- | --- | --- | --- |
| 后端 | 2 核 | 2 GB | 10 GB |
| MongoDB | 4 核 | 8 GB | 按实例量评估，建议 SSD |
| RabbitMQ | 2 核 | 4 GB | 20 GB |
| ZooKeeper | 2 核 | 2 GB | 10 GB |

> MongoDB 容量估算：单实例文档内含完整 DSL 与关系图，约占几十 KB；按日运行量 × 保留天数估算，并预留索引空间。

## §3 构建产物

### 3.1 全量构建

```bash
git clone <仓库地址> service-arrange
cd service-arrange/backend
mvn clean package -DskipTests
```

产物位置：

| 模块 | 产物 |
| --- | --- |
| 根工程 / backend | 无独立产物 |
| `backend/engine` | `backend/engine/target/*.jar`（库包）|
| `backend/web` | `backend/web/target/service-arrange.jar`（可执行 Spring Boot jar）|

### 3.2 只构建 Web 模块

```bash
cd backend
mvn -pl web -am clean package -DskipTests
```

`-am` 表示同时构建其依赖模块（`engine`）。

### 3.3 前端无需构建

`frontend/` 是纯静态目录，**没有构建步骤**，直接拷贝即可部署。

## §4 部署中间件

### 4.1 MongoDB

```bash
# 单机
mongod --dbpath /data/mongodb --port 27017 --bind_ip 0.0.0.0

# 副本集（生产建议）
mongod --replSet rs0 --dbpath /data/mongodb --port 27017 --bind_ip 0.0.0.0
mongo --eval 'rs.initiate()'
```

> 注意：`application.yml` 中 `database` 配置为 **`admin`**（系统库）。建议生产改为独立业务库 `servicearrange`，见 [配置说明](12-配置说明.md) §6。

### 4.2 RabbitMQ

```bash
rabbitmq-server -detached

# 启用管理插件
rabbitmq-plugins enable rabbitmq_management

# 创建专用账号（不要用 guest，guest 仅允许本机登录）
rabbitmqctl add_user app '<强密码>'
rabbitmqctl set_permissions -p / app ".*" ".*" ".*"
```

交换器与队列说明：

| 项 | 值 |
| --- | --- |
| 交换器 | `servicearrange-exchange-point`（由 `${spring.application.name}-exchange-point` 生成）|
| 任务队列 routing key | `/task/run` |
| 结果队列 routing key | `/task/result` |
| 生产路由键来源 | 消息头 `headers.receiveSign` |
| 消费 ACK 模式 | `manual` |

### 4.3 ZooKeeper

```bash
# 单机
zkServer.sh start

# 集群：3 节点，各自 zoo.cfg 配置
tickTime=2000
dataDir=/data/zookeeper
clientPort=2181
initLimit=10
syncLimit=5
server.1=zk1:2888:3888
server.2=zk2:2888:3888
server.3=zk3:2888:3888
```

锁路径：`/INST_LOCK_{instId}`，`CreateMode.EPHEMERAL`。

## §5 部署后端

### 5.1 方式一：直接运行 jar

```bash
# 1. 准备配置（推荐用环境变量覆盖，见配置说明 §6）
export MONGO_HOST=10.0.0.11
export MONGO_USERNAME=app
export MONGO_PASSWORD='***'
export MQ_ADDRESSES=10.0.0.12:5672
export MQ_USERNAME=app
export MQ_PASSWORD='***'
export ZK_URL=10.0.0.13:2181

# 2. 启动
nohup java -jar web/target/service-arrange.jar \
  --spring.profiles.active=prod \
  > /var/log/service-arrange/app.log 2>&1 &
```

### 5.2 方式二：systemd 托管（推荐）

创建 `/etc/systemd/system/service-arrange.service`：

```ini
[Unit]
Description=Service Arrange Platform
After=network.target

[Service]
Type=simple
User=appuser
WorkingDirectory=/opt/service-arrange
EnvironmentFile=/opt/service-arrange/.env
ExecStart=/usr/bin/java -Xms1g -Xmx2g -jar /opt/service-arrange/service-arrange.jar
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

`.env` 文件（权限设为 `600`）：

```
MONGO_HOST=10.0.0.11
MONGO_USERNAME=app
MONGO_PASSWORD=***
MQ_ADDRESSES=10.0.0.12:5672
MQ_USERNAME=app
MQ_PASSWORD=***
ZK_URL=10.0.0.13:2181
```

```bash
systemctl daemon-reload
systemctl enable --now service-arrange
systemctl status service-arrange
journalctl -u service-arrange -f
```

### 5.3 方式三：Docker 运行

见 §7。

### 5.4 DSL 文件投放

后端**固定读取** classpath 下的 `hrh_http.json`（见 [项目现状](10-项目现状.md) 缺陷 P1）。投产时有两种处理：

| 方式 | 操作 |
| --- | --- |
| 打包前进资源 | 把目标 DSL 覆盖到 `backend/web/src/main/resources/hrh_http.json` 后再 `mvn package` |
| 启动参数外置 | 若后续改造为可配置路径，用 `--servea.dsl-path=/data/dsl/main.json` 指定 |

> 当前代码**未支持**第二种方式，需先完成 `Plan` 实体改造。

## §6 部署前端

### 6.1 方式一：Nginx 托管（推荐）

```nginx
server {
    listen 80;
    server_name arrange.example.com;

    # 前端静态资源
    root /opt/service-arrange/frontend;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # 反向代理后端，解决跨域
    location /servicearrange/ {
        proxy_pass http://127.0.0.1:8082/servicearrange/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }
}
```

> 采用此方案后，前端「接口设置」可**留空**（同源），请求 `/servicearrange/...` 会被 Nginx 转发到后端。同时后端能收到真实的请求头（`#header_$Xxx` 取值依赖此项）。

部署命令：

```bash
cp -r frontend/* /opt/service-arrange/frontend/
nginx -t && nginx -s reload
```

### 6.2 方式二：由后端托管（最简）

把 `frontend/` 下所有文件拷入后端资源目录：

```bash
cp -r frontend/* backend/web/src/main/resources/static/
```

目录结构：

```
static/
├── index.html
├── css/style.css
└── js/*.js
```

重新打包并启动后，访问 `http://{host}:8082/servicearrange/index.html`。

> 优点：无需 Nginx、无跨域问题。缺点：前端更新需重新打包后端。

### 6.3 方式三：独立静态服务

```bash
cd frontend
npx serve . -l 5173
```

在页面右上角「接口设置」填入后端完整地址（含上下文路径）。

## §7 容器化部署

### 7.1 后端 Dockerfile

```dockerfile
FROM maven:3.8-openjdk-8 AS builder
WORKDIR /build
COPY pom.xml .
COPY engine/pom.xml engine/
COPY web/pom.xml web/
RUN mvn dependency:go-offline -B
COPY . .
RUN mvn clean package -DskipTests

FROM openjdk:8-jre-slim
WORKDIR /app
COPY --from=builder /build/backend/web/target/*.jar app.jar

ENV TZ=Asia/Shanghai
ENV JAVA_OPTS="-Xms1g -Xmx2g"

EXPOSE 8082
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]
```

### 7.2 前端 Dockerfile

```dockerfile
FROM nginx:1.24-alpine
COPY frontend/ /usr/share/nginx/html/
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

### 7.3 docker-compose（一体化）

```yaml
version: '3.8'
services:
  mongodb:
    image: mongo:4.4
    environment:
      MONGO_INITDB_ROOT_USERNAME: admin
      MONGO_INITDB_ROOT_PASSWORD: ${MONGO_PASSWORD}
    volumes:
      - mongo_data:/data/db
    ports:
      - "27017:27017"

  rabbitmq:
    image: rabbitmq:3.11-management
    environment:
      RABBITMQ_DEFAULT_USER: app
      RABBITMQ_DEFAULT_PASS: ${MQ_PASSWORD}
    ports:
      - "5672:5672"
      - "15672:15672"

  zookeeper:
    image: zookeeper:3.8
    environment:
      ZOO_4LW_COMMANDS_WHITELIST: "*"
    ports:
      - "2181:2181"

  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    environment:
      MONGO_HOST: mongodb
      MONGO_USERNAME: admin
      MONGO_PASSWORD: ${MONGO_PASSWORD}
      MQ_ADDRESSES: rabbitmq:5672
      MQ_USERNAME: app
      MQ_PASSWORD: ${MQ_PASSWORD}
      ZK_URL: zookeeper:2181
    ports:
      - "8082:8082"
    depends_on:
      - mongodb
      - rabbitmq
      - zookeeper

  frontend:
    build:
      context: .
      dockerfile: frontend/Dockerfile
    ports:
      - "80:80"
    depends_on:
      - backend

volumes:
  mongo_data:
```

启动：

```bash
echo "MONGO_PASSWORD=***" > .env
echo "MQ_PASSWORD=***" >> .env
docker-compose up -d
docker-compose logs -f backend
```

### 7.4 K8s 部署要点

| 项 | 说明 |
| --- | --- |
| 无状态化 | 后端本身无状态，锁在 ZK，可自由扩缩容 |
| 副本数 | **必须先完成 MQ 投递改造**，否则副本数只能为 1 |
| 探针 | 当前无 actuator，建议先引入 `/actuator/health` 再做 liveness/readiness |
| 配置 | 用 ConfigMap 放非敏感项，Secret 放密码 |
| 优雅停机 | 设置 `preStop` 钩子，等待在途任务完成 |

## §8 部署后校验

### 8.1 逐项检查

| 序号 | 检查项 | 方法 | 期望 |
| --- | --- | --- | --- |
| 1 | 后端进程 | `ps -ef \| grep java` 或 `systemctl status` | 运行中 |
| 2 | 端口监听 | `netstat -ano \| grep 8082` | LISTENING |
| 3 | 启动日志 | `tail -f app.log` | 见 `Started ServiceArrangeApplication`，无异常堆栈 |
| 4 | Mongo 连通 | 接口调用后查 `SERVEA_INST` | 有新文档产生 |
| 5 | MQ 连通 | RabbitMQ 管理台查队列 | `servicearrange-exchange-point` 交换器存在 |
| 6 | ZK 连通 | `zkCli.sh -server host:2181` → `ls /` | 可连接，无 Curator 告警 |
| 7 | 接口可达 | `curl -X POST ".../registerOperator/save" -H "Content-Type: application/json" -d '{...}'` | 返回 `success` |
| 8 | 前端加载 | 访问 `http://host/index.html` | 页面正常渲染 |
| 9 | 前端联调 | 点「接口设置 → 连通性检测」 | 顶栏显示「已连通」 |
| 10 | 编排闭环 | 加载示例 1 → 校验 → 导出 DSL | 校验通过，JSON 规范 |

### 8.2 冒烟测试命令

```bash
# 算子查询（探针）
curl "http://localhost:8082/servicearrange/registerOperator/findById?id=1"

# 保存算子
curl -X POST "http://localhost:8082/servicearrange/registerOperator/save" \
     -H "Content-Type: application/json" \
     -d '{"type":"http","serviceName":"测试","serviceUrl":"localhost/demo","requestMethod":"get"}'

# 运行实例
curl -X POST "http://localhost:8082/servicearrange/inst/run/or/getResult/PLAN_001" \
     -F "servea_optType=run" -F "servea_sync=false"
```

### 8.3 回滚方案

| 场景 | 操作 |
| --- | --- |
| 后端异常 | 保留上一版本 jar，`systemctl stop` 后替换 jar 再 `start` |
| 前端异常 | 静态目录改名回滚（如 `frontend` ↔ `frontend.bak`），`nginx -s reload` |
| 配置错误 | 恢复 `.env` 中上一版环境变量后重启 |
| 数据异常 | 按 `instId` 清理 `SERVEA_INST` / `SERVEA_TASK` / `SERVEA_INST_LOG` 中的对应记录 |
