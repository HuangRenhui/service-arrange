## §1 总览

```
① 解析   DslParser.parser(dslStr)              → Inst（内存图，落库 SERVEA_INST）
② 转换   TaskInterface.convert(cell, inst)     → Task（落库 SERVEA_TASK）
③ 执行   Execute.run(taskId)                   → 节点状态 + outputs
            └─ 内部委托 Execute.runProcess(task, inst, taskDao, instLogDao)
④ 编排   TaskResultConsumer.run(...)           → 下一批节点 / 补偿 / 循环 / 决策
```

第 ③④ 步通过 RabbitMQ 解耦。**实例内串行、实例间并行**：

- 单实例同一时刻只允许一个节点在跑，用 ZooKeeper `EPHEMERAL` 节点 `Inst.ZK_LOCK_PREFIX + instId` 做实例锁（`TaskResultConsumer` L82-91）；
- 拿不到锁就 `nack` 重排队（L90），保证同一实例的结果消息不会被并发处理；
- 不同实例互不影响，消费者可水平扩容。

> 注意：当前 `TaskProductor.sendTaskResult` / `sendTaskRun`（L38-51）是**直接方法调用**而非真正投递 MQ，`MqChannelProcessor` 中定义的 `output_channel` 等通道目前未被使用。广播语义靠 `@StreamListener` 注解保留。

## §2 解析阶段：`DslParser.parser`

`DslParser`（`parser/DslParser.java` L53-237）把 DSL JSON 变成可调度图。

### 2.1 解析步骤

| 步骤 | 行号 | 说明 |
| --- | --- | --- |
| 反序列化 | L54 | `JSONUtil.toBean(dslStr, DSL.class)` |
| 拆分元素 | L57-59 | 过滤出业务节点 `cells` 与全局参数节点 `globalDatas` |
| 取首尾节点 id | L61 | `node_start` / `node_end` |
| 取所有连线 | L63 | 四类 `edge_*` |
| 源/目标集合 | L66-68 | **排除 `edge_loop`**：循环线不代表实际流转 |
| 孤立节点 | L70-75 | 既非首尾、非连线、也不在任何线两端的节点 |
| 真实入口 | L79 | `srcNodeIds - tarNodeIds`（例：线 1-2、2-3 → src={1,2}、tar={2,3} → 根={1}）|
| 真实出口 | L82 | `tarNodeIds - srcNodeIds` → 上例得到 {3} |
| 构建图 | L85-94 | `nodeChildsMap` / `nodeParentsMap` / `nodeInputEdgesMap` / `nodeOutEdgesMap` / `nodeMap` |
| 孤立节点补挂 | L96-99 | 同时加入 `roots` 与 `ends`，避免不可达 |
| 遍历连线填表 | L101-132 | 逐条线补齐父子、入度线、出度线 |
| 挂虚拟开始节点 | L139-147 | `startId` 的 children ← 真实根节点集合；这些节点的 parent 强制置为 `{startId}` |
| 挂虚拟结束节点 | L152-157 | 真实出口节点的 parent ← `{endId}`；`endId` 的 children ← 真实出口集合 |
| 隐藏首尾直连 | L162-163 | `startId → endId` 互挂，保证空流程也能结束 |
| 处理强组合 | L167-179 | 由 `cell.groupIds` **反向填充** `group.nodes` |
| 组装 Inst | L180-190 | 写入 `roots`（**只有 startId**）、`totalNodes`、`waitingNodes`（初值 = 全部节点）、`nodeMap`、`groups` |
| 全局参数 | L192-229 | `staticParams` / `dynamicParams` → `KeyValueDto`，`key = name`、`value = defaultValue = default`，名称做 `trim` 去 `\t\r` |
| 循环区间 | L231-235 | 每条循环线算一次区间，写入 `loopRunTimesMap[edgeId] = NodeLoopInfo(edgeId, ids, 0)` |

### 2.2 循环区间推导 `getCellIdsBetweenLoopEdge`（L239-259）

循环线 `source → target` 圈定的区间 = 「source 的所有祖先」∩「target 的所有后代」，再加两端点：

```
source 的所有父（含传递闭包） = myParents      // getMyParents 递归，L280-294
idsbetween = {source, target}
getChildNotInSet(...)   // 从 target 向下收集「仍属于 myParents」的后代，L263-275
最后把两端都在 idsbetween 内的连线也纳入区间（L255-257）
```

> 注意 L261、L278 使用 `static` 计数器 `Chilednum` / `Parentnum` 做递归出口，属于**非线程安全**实现；解析是单线程调用所以未暴露问题，但并发调用 `parser` 会有风险。

### 2.3 `Inst` 的图字段

| 字段 | 语义 |
| --- | --- |
| `roots` | 入口集合，固定只放 `startId` |
| `nodeChildsMap` | 节点 → 子节点 |
| `nodeParentsMap` | 节点 → 父节点 |
| `nodeInputEdgesMap` | 节点 → 入度连线 id |
| `nodeOutEdgesMap` | 节点 → 出度连线 id |
| `nodeMap` | id → Cell（含连线） |
| `groups` | 强组合列表 |
| `loopRunTimesMap` | 循环线 id → `NodeLoopInfo(区间, 已循环次数)` |
| `totalNodes` / `waitingNodes` / `successNodes` / `failNodes` / `skipNodes` | 调度状态集合 |
| `staticParams` / `dynamicParams` | 全局参数 |

## §3 转换阶段：Cell → Task

### 3.1 接口契约

`TaskInterface`（`convert/TaskInterface.java`）是转换器统一契约，实现类以 **`cellType + "_task"`** 注册为 Spring Bean（`TaskType.suffix`）。

接口由「一个模板方法 + 一个抽象方法」组成：

```java
public interface TaskInterface {
    /** 模板方法：填充 Task 公共字段 + 计算 loopTimes，再委托 process */
    default Task convert(Cell cell, Inst inst) { ... }

    /** 子类实现：仅需转换 task 的入参 */
    Task process(Cell cell, Inst inst, Task task);
}
```

> ⚠️ 子类实现的是 **`process`**，不是 `convert`。`convert` 是模板方法，负责公共字段装配，**不要重写**。

`convert` 模板方法（L19-46）的固定装配逻辑：

| 步骤 | 行号 | 说明 |
| --- | --- | --- |
| `nodeName` | L21-25 | 为空时回退 `cellType + "_" + id` |
| `instId` / `planId` / `nodeId` | L26-28 | 从 `inst` 与 `cell` 取 |
| `createDate` / `modifyDate` | L29-31 | 当前时间 |
| `type` | L32 | = `cell.getCellType()`，供执行器路由 |
| `state` | L33 | 初始为 `STATE_WAITE` |
| `loopTimes` | L35-42 | 取**区间最小**的循环线 → `循环线id\|次数`；不在循环内为 `"0"` |
| 委托子类 | L43 | `task = this.process(cell, inst, task)` |

**`loopTimes` 推导**（L35-42）：先筛出「区间包含本节点」的所有循环线，再按区间大小升序取第一个（即**最近一层循环**）。示例见 `TaskServiceImpl` L70 的注释：`A-B-C-D-E-F` 中存在 `B-E` 与 `D-E` 两条循环线时，节点在 `D-E` 内应取 `D-E`。

### 3.2 已实现的转换器

| 转换器 | Bean 名 | `process` 实现要点 |
| --- | --- | --- |
| `StartTask` | `node_start_task` | 将 `inst.dslInputParams` 写入 `outputs.value`；`outputs.jsonSchema` 取开始节点 Schema；`headerParams` 取实例请求头；直接置 `SUCCESS` 并补齐全部时间字段 |
| `EndTask` | `node_end_task` | 把 `EndCell.data` 序列化后放入 `task.inputs`；`outputs.contentType` / `jsonSchema` 取自节点配置；`headerParams` 取实例请求头（**实际出参映射由 `EndOperateExecutor` 完成**）|

### 3.3 运行时获取

三处按需获取（`TaskResultConsumer` L177 补偿、L243 doWhile、L365 常规下一节点）：

```java
TaskInterface ti = SpringUtil.getBean(cell.getCellType() + TaskType.suffix);
Task t = ti.convert(cell, inst);   // 内部会委托到子类的 process
```

> `TaskType.java` 中除 `START` / `END` / 四个 `EDGE_*` 外，其余常量被整体注释（L25-47），实际全靠 `cellType + "_task"` 约定。新增节点类型时**只要保证 Bean 名符合约定即可被调度**。

## §4 执行阶段：`Execute`

### 4.1 路由规则（`TaskRunConsumer` L55-88）

```java
if (FUN_JAR or FUN_PYTHON) execute = getBean(CellType.FUN_SHELL);
else                        execute = getBean(task.getType());
```

即 **Jar / Python 复用 Shell 执行器**（都是「本机子进程」语义），其余节点按 `type` 直取同名 Bean。

### 4.2 消费端保障

| 机制 | 行号 | 说明 |
| --- | --- | --- |
| 手工 ACK | L38-51 | 使用 `AmqpHeaders.CHANNEL` + `DELIVERY_TAG` |
| 参数校验 | L47-50 | id / type 为空直接 ack 丢弃 |
| 任务不存在 | L59-62 | ack 丢弃 |
| 重试上限 | L63-66 | `runNackTimes >= 5` 强制 ack，避免死循环 |
| 异常兜底 | L80-87 | `runNackTimes++` 落库后 `nack`（requeue=true）|

### 4.3 `Execute` 接口（真实定义）

```java
public interface Execute {
    /** 模板方法：加载任务 → 置 RUNNING → 执行 → 状态归一 → 回传结果 */
    default void run(String tid) { ... }

    /** 子类实现：真正的节点执行逻辑，返回处理后的 task */
    Task runProcess(Task task, Inst inst, TaskDao taskDao, InstLogDao instLogDao);
}
```

`run(tid)`（L23-45）的关键行为：

| 步骤 | 行号 | 说明 |
| --- | --- | --- |
| 查任务 | L28 | 不存在则构造一个 `STATE_FAIL` 的占位 Task |
| 查实例 | L36 | `instDao.findById(task.getInstId())` |
| 置运行中 | L35 | `task.setState(STATE_RUNNING)` |
| 计时 | L37 / L43 | `executorStartDate` / `executorEndDate` |
| 调用子类 | L38 | `runProcess(task, inst, taskDao, instLogDao)` |
| 状态归一 | L39-41 | 只要不是 `FAIL`，统一置为 `SUCCESS` |
| 回传结果 | L44 | `taskProductor.sendTaskResult(task)` ← **必调，否则流程卡死** |

### 4.4 执行器清单

| cellType | Execute 实现 | 说明 |
| --- | --- | --- |
| `node_start` | `StartOperateExecutor` | 置成功；含 `debug` 分支；提供 `getDataByNodeIds` 公共取值方法 |
| `node_end` | `EndOperateExecutor` | 按 `contentType` 分三路汇总出参：JSON-Schema 单值 / JSON-Schema 对象 / 非 JSON 表达式取值 |
| `node_inner_datamap` | `DataMapOperateExecutor` | 五类入参映射 + `valueCompute` 表达式求值（被 `TaskServiceImpl` 与 `EndOperateExecutor` 复用）|
| `node_outer_http` | `HttpTaskExecutor` | Hutool `HttpUtil` 发起请求；支持 GET/POST/PUT；状态码 ≠200 或响应含 `error` 关键字判失败；含文件表单上传（文件获取为 TODO）|

其余类型（Dubbo / WebService / Shell / Jar / Python / JSON↔XML / 补偿类 / sleep / decision / dataresult / transform2Obj）**尚未提供 Execute 实现**。

## §5 编排阶段：`TaskResultConsumer.run`

这是最复杂的一环（L104-441），按顺序做 6 件事。

### 5.1 前置校验与状态落库

| 步骤 | 行号 | 说明 |
| --- | --- | --- |
| 入参校验 | L105-108 | id / instId / state 任一为空则 ack |
| 查任务与实例 | L112-120 | 任一不存在则 ack |
| 挂起检查 | L121-126 | 实例为 `SUSPEND` 时把 `节点名\|循环次数` 记入 `suspendNodes` 后 ack，**不推进流程** |
| 重试上限 | L128-131 | `stateNackTimes >= 5` 强制 ack |
| 状态归档 | L133-145 | 按 state 写入 `skipNodes` / `successNodes` / `failNodes`；失败时实例置 `FAIL`；保存 task 的 `retryRules` / `state` / `outputs` |

### 5.2 补偿（失败分支，L172-188）

条件：`state == FAIL` 且当前节点存在 `edge_compensate` 出线。

```
取补偿线 target 节点 → getBean(cellType + "_task") → convert → 删旧任务 → 存新任务
→ sendTaskRun(补偿任务) → ack 并 return（不再推进正常分支）
```

> 即「失败即转入补偿节点」，补偿节点自身失败会再次走同一逻辑（补偿链可嵌套）。

### 5.3 doWhile 循环（L194-258）

触发条件：`state == SUCCESS` 且当前节点有 `edge_loop` 出线且 `loopType == doWhile`。

```
1. 依 cycleInfo 更新动态全局参数：dynamicParams[idx].value = value <rule> <stepLength>（SpEL 求值）
2. edgeLoopDecisionDo(...) 求循环条件
3. 成立 → NodeLoopInfo.times++；把区间内节点从 success/fail/skip 移除、重新加入 waitingNodes
        → 转 target 节点为任务并 sendTaskRun → return
4. 不成立 → 区间内节点整体标记为成功（视为已跑完）
```

### 5.4 结束节点（L261-271）

`task.type == node_end` 时：写 `endDate`，成功则实例置 `SUCCESS` 并把 end 任务的 outputs 作为实例出参，否则置 `FAIL`，然后 return。

### 5.5 whileDo 预判（L274-340）

对当前节点的每个子节点，检查其入度线里是否存在 `loopType == whileDo` 的循环线：

```
依 cycleInfo 更新动态参数（与 doWhile 同构）
whileDo 判定：
  false → 区间内节点从 waiting/skip 移除；当前子节点从本轮移除；
          改为把循环线 source 的子节点加入待执行（跳出循环继续向下）
  true  → NodeLoopInfo.times++
```

> `whileDo` 与 `doWhile` 的区别：`whileDo` 在**进入区间前**判条件，且条件只能引用动态全局参数；`doWhile` 在**区间跑完后**判条件，可引用区间内节点输出。

### 5.6 下一批节点与决策线（L343-427）

对每个候选下一节点 `ii`：

1. **过滤父节点**：剔除仅由循环线连接的父节点（L352-358），避免循环线参与「父节点全成功」判断；
2. **就绪判断**：`psuccessNum == pids.size()` 才转 Task（L361-362）；
3. **落地任务**：`convert` → 按 `nodeId + loopTimes` 删旧存新（L365-372）；
4. **SKIP 传播**：若父节点全为 skip → 子节点也生成 SKIP 结果（L388-393）；
5. **决策线校验**：`trueCount == dicisionEdges.size()` 才 `sendTaskRun`，否则置 SKIP（L396-415）；
6. 无决策线则直接执行（L417-418）；
7. 清理 `waitingNodes`，并把入度线也标记为 skip（L421-426）。

## §6 表达式求值：`TaskServiceImpl`

`ITaskService`（`service/ITaskService.java`）提供两个方法：

```java
Boolean edgeDecisionDo(String startId, String instId, String exp, String[] R, String[] L,
                       List<ConditionData> conditionData, Task task);
Boolean edgeLoopDecisionDo(String startId, String instId, String exp, String[] r, String[] l, Task task);
```

`edgeLoopDecisionDo` 直接委托 `edgeDecisionDo`（L166-168）。

### 6.1 求值算法（L47-163）

| 步骤 | 行号 | 说明 |
| --- | --- | --- |
| 提取节点 id | L49-61 | 从表达式中用 `subBetweenAll("#pno_", "$")` / `("#header_", "$")` 抠出依赖节点 |
| 取节点输出 | L62-78 | 查该实例下这些节点的 Task，**按循环次数匹配**（`loopEdgeId\|times`），最近（区间最小）的循环线优先 |
| 计算 R 值 | L80-100 | `#dynamicParams$` → 从实例动态参数取；`null` 字面量保留；否则走 `valueCompute` |
| R 代入 | L101-107 | `string` 类型加单引号，其余裸填 |
| 计算 L 值 | L109-157 | 支持 `#pno_…$`、`null`、脚本求值（`ScriptUtil.eval`），失败则原样代入 |
| SpEL 求值 | L158-160 | `new SpelExpressionParser().parseExpression(exp).getValue()` |

### 6.2 取值表达式语法

| 写法 | 含义 |
| --- | --- |
| `#节点id$jsonpath` | 取指定节点输出的某字段 |
| `#pno_节点id$field` | 指向上游节点（parent node output）|
| `#header_$X-AToken` | 取请求头 |
| `#dynamicParams_$idx` / `#dynamicParams$idx` | 取动态全局参数 |
| `#start_$where` | 取开始节点入参的 `where` 字段 |

## §8 已知实现缺陷（仅记录，不在本次范围内修复）

| 位置 | 问题 |
| --- | --- |
| `TaskResultConsumer` L381-385 | `dicisionEdges` 恒为 `null`（`filter(...)` 结果未接收），**决策线分支实际永不执行**，L396 条件恒假 |
