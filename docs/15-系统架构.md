### 1.2 逻辑分层（概念模型）

```
契约     DSL JSON（节点 + 连线 + 强组合）        ← 唯一契约，前后端共同遵守
内核     解析 · 调度 · 决策 · 循环 · 补偿 · 求值
算子     HTTP · Dubbo · WebService · 脚本 · 内部算子
基础设施 Mongo · RabbitMQ · ZooKeeper
```

## §4 数据流向

### 4.1 流程建模与运行（主流程）

```
用户在画布编排
    ▼
Store.toDSL(model)          剔除视图字段，补全 name/ports，反向填充 groups.nodes
    ▼
DslValidator.validate()     校验 R1~R9
    ▼
DSL JSON ─────────────────────────────────────────────┐
    ▼                                                 │
DslParser.parser(dsl)      构建 nodeMap / 父子关系     │
    │                        / 入出度 / 循环区间        │
    ▼                                                 │
Inst（落库 SERVEA_INST）                              │
    ▼                                                 │
StartTask.convert()        roots 首个节点 → Task      │
    ▼                                                 │
TaskProductor.sendTaskResult()  （当前为本地直调）      │
    ▼                                                 │
TaskResultConsumer.run()   加 ZK 锁 → 状态落库         │
    │                      → 补偿/循环/决策           │
    │                      → 计算下一批节点           │
    ▼                                                 │
TaskRunConsumer → Execute.runProcess()  执行算子      │
    │                                                 │
    └──────── 回传结果，循环推进至 node_end ───────────┘
    ▼
实例 outputs 落库 → 接口返回
```

### 4.2 算子注册（辅助流程）

```
算子注册表单（20 个字段）
    ▼
Api.saveOperator() → RegisterInfoController.save()
    ▼
REGISTER_INFO 集合
    ▼
供编排设计时复用（登记外部 API 元信息：地址、入参出参 Schema、超时等）
```

### 4.3 运行实例查询

```
运行实例表单（按开始节点 inputsJsonSchema 自动生成）
    ▼
SchemaUtil.castValue() 按声明类型还原（text/array/number/boolean/object）
    ▼
Api.runOrGetResult() → InstController
    ▼
optType=run         → 新建实例并触发执行
optType=get_result  → 读取本次实例状态与出参
```

## §5 部署架构

### 5.1 开发环境

| 项 | 说明 |
| --- | --- |
| 拓扑 | 单机：前端静态页 + 后端单实例 + 单节点中间件 |
| 前端 | 浏览器打开 `index.html`，或 `npx serve .` |
| 后端 | `mvn spring-boot:run`，监听 `:8082` |
| 中间件 | 本机 MongoDB `:27017` / RabbitMQ `:5672` / ZooKeeper `:2181` |
| 跨域 | `file://` 直接打开时受 CORS 限制，仅做编排不受影响 |

### 5.2 生产环境（建议）

```
                    ┌──────────────┐
                    │  Nginx / LB  │
                    └───────┬──────┘
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
     ┌─────────────────┐        ┌─────────────────┐
     │ 静态资源（前端） │        │ 后端实例 × N    │
     │ /index.html 等  │        │ :8082           │
     └─────────────────┘        └────────┬────────┘
                                         │
                    ┌────────────────────┼────────────────────┐
                    ▼                    ▼                    ▼
            ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
            │  MongoDB     │    │  RabbitMQ    │    │  ZooKeeper   │
            │  副本集       │    │  集群        │    │  集群        │
            └──────────────┘    └──────────────┘    └──────────────┘
```

> ⚠️ **后端多实例的前提**：`TaskProductor` 必须改为真正投递 MQ（当前为本地直调）。否则实例 A 生成的任务结果不会流转到实例 B，多实例部署无意义。详见 [项目现状](10-项目现状.md) 缺陷 P2。

## §6 安全设计

### 6.1 当前已具备

| 序号 | 机制 | 说明 |
| --- | --- | --- |
| 1 | 分布式锁防并发 | ZooKeeper 临时节点保证同一实例结果串行处理 |
| 2 | 消费端手工 ACK | 处理失败可 nack 重排队，避免消息丢失 |
| 3 | 重试上限保护 | `runNackTimes` / `stateNackTimes` ≥ 5 强制 ack，防毒消息死循环 |
| 4 | 前端输入校验 | Schema JSON 合法性、DSL 规则 R1~R9 |
| 5 | 删除二次确认 | 清空画布、删除节点均有确认弹窗 |

### 6.2 当前缺失（需补齐）

| 序号 | 风险 | 建议 |
| --- | --- | --- |
| 1 | **无认证授权** | 接口裸奔，任何人可运行流程、篡改算子注册。需接入统一认证（如 JWT / OAuth2）|
| 2 | **配置明文密码** | MongoDB `123456`、MQ `guest` 硬编码在 YAML。改用环境变量或配置中心 |
| 3 | **公网 IP 硬编码** | 中间件地址写死 `8.129.116.16`。改用内网地址或服务发现 |
| 4 | **脚本算子无沙箱** | Shell / Jar / Python 算子（待实现）若直接执行用户脚本存在命令注入风险。需白名单 + 沙箱 + 资源限制 |
| 5 | **表达式注入** | 决策线使用 SpEL 求值，若表达式可由外部输入构造，存在 RCE 风险。需限定表达式白名单或改用安全求值器 |
| 6 | **DSL 无签名** | 流程模型可被任意篡改。需加版本号 + 校验和 |
| 7 | **无操作审计** | 谁在何时运行了什么流程、改了哪个算子，无记录 |
| 8 | **无接口限流** | 运行接口可被刷，导致实例爆炸 |
| 9 | **SSRF 风险** | HTTP 算子可访问任意 URL（含内网地址）。需域名/IP 白名单 |

### 6.3 安全基线清单

上线前应逐项确认：

- [ ] 接口已接入认证，且按角色区分「只看 / 可编辑 / 可运行」
- [ ] 所有密码、密钥来自环境变量或密钥管理服务，仓库中无明文
- [ ] 中间件仅监听内网，不暴露公网端口
- [ ] 脚本类算子启用白名单与执行超时
- [ ] SpEL 表达式受限（禁用 `T()`、`Runtime`、`ProcessBuilder` 等）
- [ ] HTTP 算子配置目标域名白名单
- [ ] 运行接口按租户/用户限流
- [ ] 关键操作（运行、保存、删除）写审计日志

## §7 性能设计

### 7.1 当前设计

| 序号 | 机制 | 说明 |
| --- | --- | --- |
| 1 | 实例内串行 | 同一实例同一时刻只有一个节点在跑，简化状态管理 |
| 2 | 实例间并行 | 不同实例互不影响，消费者可水平扩容 |
| 3 | Mongo 字段投影 | `InstDao` 的 `findStateById` / `findSyncById` / `findOutputsById` 只回传必要字段 |
| 4 | 任务去重 | 按 `nodeId + loopTimes` 删旧存新，避免重复任务堆积 |
| 5 | 循环区间预计算 | 循环范围在解析阶段一次性算好，运行期不再遍历图 |
| 6 | 消费并发可配 | `consumer.concurrency` 当前为 `1`，可按压测上调 |

### 7.2 优化方向

| 序号 | 问题 | 优化建议 |
| --- | --- | --- |
| 1 | 实例内串行限制吞吐 | 对无依赖的并行分支做「同层并行」，用节点级锁替代实例级锁 |
| 2 | 消费并发为 1 | 压测后上调；注意与实例锁的配合 |
| 3 | 每节点多次查库 | 引入实例级缓存，把 `inst` 常驻内存（`syncInstMap` 已有雏形）|
| 4 | 决策求值重复查任务 | `TaskServiceImpl` 每次按节点查 Task，可批量预取 |
| 5 | 无缓存 | 算子注册、DSL 解析结果可加本地/分布式缓存 |
| 6 | 大对象入库 | `Inst` 内含完整 DSL 与全部关系图，单文档较大。可拆分子集合 |

## §8 监控与日志

### 8.1 当前状态

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 日志落库 | ✅ | `InstLog` 集合，级别 `LEVEL_INFO` / `LEVEL_WARN` / `LEVEL_ERRO` |
| 节点级日志 | ✅ | HTTP 执行器记录开始/成功/失败/异常及返回信息 |
| 执行计时 | ✅ | `startDate` / `endDate` / `executorStartDate` / `executorEndDate` |
| 日志查询接口 | ❌ | 无 |
| 实例列表 / 详情 | ❌ | 无 |
| 健康检查端点 | ❌ | 未引入 actuator |
| 指标采集 | ❌ | 无 Micrometer / Prometheus |
| 链路追踪 | ❌ | 无 traceId / spanId |
| 告警 | ❌ | 无 |

### 8.2 建议补齐

| 序号 | 项 | 建议方案 |
| --- | --- | --- |
| 1 | 健康检查 | 引入 `spring-boot-starter-actuator`，暴露 `/actuator/health` |
| 2 | 指标采集 | Micrometer + Prometheus，暴露实例数、任务耗时、失败率、MQ 积压 |
| 3 | 链路追踪 | 生成 `traceId` 注入 `InstLog`，贯穿实例 → 任务 → 算子 |
| 4 | 日志查询 | 新增 `/instlog/list` 接口，支持按 instId / nodeId / level 过滤 |
| 5 | 实例看板 | 前端新增「实例监控」页，展示状态分布、耗时TopN、失败节点 |
| 6 | 告警 | 实例 FAIL 数超阈值、MQ 积压超阈值时告警 |
| 7 | 执行轨迹 | 持久化节点流转路径，支持回放 |

## §9 扩展性设计

### 9.1 已具备的扩展点

| 序号 | 扩展点 | 机制 | 扩展成本 |
| --- | --- | --- | --- |
| 1 | 新增算子 | Bean 名约定 `cellType` / `cellType + "_task"`，无需改引擎 | 低 |
| 2 | 新增节点类型（前端） | `js/nodes.js` 追加一项即可出现在节点库 | 低 |
| 3 | 新增 DSL 字段 | Cell 子类加字段（Hutool 自动映射）| 低 |
| 4 | 算子复用 | `TaskRunConsumer` 中的复用分支（如 Jar/Python 复用 Shell）| 低 |
| 5 | 新增校验规则 | `js/validator.js` 的 `validate()` 追加检查 | 低 |
| 6 | 新增接口 | 在 `web` 模块的 Controller 中追加 | 低 |

### 9.2 应补齐的扩展能力

| 序号 | 能力 | 说明 |
| --- | --- | --- |
| 1 | 子流程 / 子编排 | 支持把一个流程作为节点嵌入另一个流程，提升复用 |
| 2 | 流程模板 | 内置常用编排模板（如「查询-校验-写入-通知」）|
| 3 | 定时触发 | Cron 触发实例，无需外部调用接口 |
| 4 | 事件触发 | 订阅 MQ 消息自动拉起实例 |
| 5 | 算子市场 | 基于 `RegisterInfoEntity` 的可视化算子选用与共享 |
| 6 | 流程版本管理 | DSL 版本化，支持回滚与灰度 |
| 7 | 多租户隔离 | 按租户隔离流程、实例与算子 |
| 8 | 插件化算子 | SPI 机制，算子可独立打包热插拔 |

### 9.3 分层扩展原则

扩展时应遵守三条边界，避免破坏现有结构：

1. **新算子不改引擎** —— 通过 Bean 命名约定接入，禁止在 `TaskResultConsumer` 中写 `if (cellType == "xxx")`；
2. **新字段不影响旧 DSL** —— Cell 子类新增字段必须有默认值，保证旧 DSL 反序列化不报错；
3. **契约变更需同步三方** —— 改 DSL 结构必须同时更新 [DSL规范](02-DSL规范.md)、`frontend/js/nodes.js`、后端 `dsl` 包。
