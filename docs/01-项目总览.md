## §1 项目定位

本项目是一个 **基于 DSL 的轻量级服务编排（Service Arrangement）引擎**。它把多个分散的服务/接口（HTTP、Dubbo、WebService、Shell/Jar/Python 脚本、内部算子）通过一份可视化编排的 JSON（DSL）串成一条可执行流程，并负责：

- 流程的**解析**（DSL → 实例图）
- 流程的**定义与发布**（Plan 草稿 / 已发布 / 停用）
- 流程的**调度与执行**（消息驱动、节点级任务、分布式锁、超时与失败重试）
- 流程的**状态与日志记录**（实例、任务、日志三级 + traceId）
- **调用幂等**（planId + idempotencyKey）
- **流程出错时的补偿与回滚**（补偿强组合）
- 流程的**循环**（doWhile / whileDo）与**条件分支**（决策线）

> 定位类比：轻量版「阿里云 OSS 工作流 / 腾讯云 TDSQL 编排 / BPMN 引擎」，更强调「服务调用」而非「人工审批」。

## §3 技术栈

| 层次 | 技术 |
| --- | --- |
| 语言/构建 | Java 8+、Maven 多模块 |
| Web | Spring Boot、Spring MVC、`spring-boot-maven-plugin` |
| 消息 | Spring Cloud Stream + RabbitMQ（4 个通道，手工 ACK）|
| 存储 | Spring Data MongoDB（`SERVEA_PLAN` / `SERVEA_INST` / `SERVEA_TASK` / `SERVEA_INST_LOG` / `REGISTER_INFO`）|
| 分布式协调 | Apache Curator + ZooKeeper（实例级分布式锁 `/INST_LOCK_{instId}`）|
| 表达式 | Spring SpEL（决策/循环条件求值）+ 自定义取值表达式 |
| 工具 | Hutool（JSON/File/StrUtil/HTTP/SpringUtil）、Lombok |
| 配置中心 | 无。Apollo 依赖与配置已移除，配置全部来自本地 `application.yml` |
| 服务注册 | 无。Eureka 依赖与配置已移除，当前以独立服务方式运行 |
| 前端 | 原生 HTML5 + CSS3 + ES5 JavaScript（零依赖、零构建）|

## §4 核心概念速览

| 概念 | 说明 |
| --- | --- |
| **DSL** | 一份 JSON，描述流程的画布元素（节点 + 连线）与强组合 |
| **Cell** | 节点或连线的统称，节点与连线同构 |
| **Inst（实例）** | 一次流程运行的上下文：解析后的图、全局参数、各节点状态集合、出参、日志 |
| **Task（任务）** | 一个节点在某个循环次数下的一次执行记录 |
| **InstLog（日志）** | 实例/节点级日志 |
| **决策线** | 条件线，条件成立才流转到目标节点 |
| **循环线** | 圈定一段区间并定义循环退出条件 |
| **补偿线 + 强组合** | 节点失败后逆序触发补偿节点，实现局部事务回滚 |
| **算子** | 可被编排的最小执行单元（HTTP/Dubbo/WebService/脚本/内部算子）|
| **算子注册** | 通过 `RegisterInfoEntity` 登记外部 API 元信息，供编排时复用 |

## §6 一次运行的端到端时序

1. 前端（或调用方）`POST /inst/run/or/getResult/{planId}` 提交表单参数。
2. `InstController` 读取 DSL、解析开始节点 `inputsJsonSchema`、把表单值按类型还原为 JSON，并采集全部请求头存入 `headerParams`。
3. `DslParser.parser(dsl)` 生成 `Inst`（图结构 + 全局参数 + 循环区间），补全 `planId/optType/sync/入参/请求头`，落库（先 `WAITE` 再 `RUNNING`）。
4. `servea_optType=run` → 取 `roots` 中的开始节点，`StartTask.convert` 生成任务，`TaskProductor` 触发执行。
5. `TaskRunConsumer` 收到任务 → 经 `CellTypeMapper.resolveExecuteType(task)` 解析真实类型（画布统一节点 `node_op` → 实际算子）→ 取到 `Execute` Bean → `runProcess` 执行 → 回写状态与出参。
6. `TaskResultConsumer` 收到结果：
   - 加实例锁（ZK 临时节点 `/INST_LOCK_{instId}`）；
   - 更新实例的 `success / fail / skip` 节点集合与实例状态；
   - 处理**补偿**（失败且有补偿线）、**循环**（doWhile / whileDo）、**决策**（决策线是否通过）；
   - 计算「所有父节点均已成功或跳过」的下一批节点，转 Task 并投递；
   - 若当前是结束节点，则落实例出参并置 `SUCCESS`。
7. `servea_optType=get_result` 时再次调用接口，读取实例状态与出参返回。

> ⚠️ 当前实现与上述设计已基本对齐：DSL 按 `planId` 从 `SERVEA_PLAN` 读取（支持 `DRAFT/PUBLISHED/DISABLED` 发布门禁）；仍偏离的一项为 **`TaskProductor` 本地直调而非真正投递 MQ**。详见 [项目现状](10-项目现状.md)。

## §8 实现状态与待办

按当前代码核对后的状态（历史待办中大部分已落地，此处只保留**仍未完成**的事项）：

| # | 位置 | 现状 |
| --- | --- | --- |
| 1 | `TaskProductor` | `sendTaskRun` / `sendTaskResult` 为**本地直调**消费者，未真正投递 MQ —— 多实例部署时任务不跨节点分发，无法水平扩容（唯一影响生产形态的结构性缺口）|
| 2 | `InstController` | 文件上传仅 `System.out.println` 未落盘；文件下载分支已消除 NPE，但流写出仍未实现 |
| 3 | `HttpTaskExecutor` | 文件类型入参的 `fileList` 收集被注释，恒为空，表单上传不可用 |
| 4 | `TaskType.java` L25-47 | 除 start/end 外的常量被整体注释，靠 `cellType + "_task"` 约定注册 |
| 5 | 命名拼写 | `Inst.starDate` / `InstLog.LEVEL_ERRO` / `RegisterInfoEntity.sheelFtpPath` |
| 6 | 观测能力 | 无 Micrometer/Prometheus 指标与告警，仅 Mongo 健康检查与业务日志 |

> 已落地项（不再列入待办）：Plan 实体与 CRUD/发布门禁、17 个 REST 接口、20 个执行器与 19 个转换器、决策/循环/补偿链路修复、traceId 贯穿、幂等、超时与失败重试、实例恢复/取消、背压保护、统一返回与全局异常处理。逐项状态见 [功能清单](09-功能清单.md)；缺陷全量清单见 [项目现状](10-项目现状.md) §3。
