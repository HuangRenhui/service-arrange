# 快速开始

本文目标：**在本地把服务编排平台跑起来**，并验证到当前代码所能支持的最大程度。

> 前置提醒：后端当前只能跑通「开始 → 结束」这一条最小链路，且 DSL 是从 classpath 固定读取的。完整能力边界见 [项目现状](10-项目现状.md) §2。前端控制台**不依赖后端**即可独立完成编排与导出。

## §0 环境要求

- **必需**
  - JDK：8 或更高（后端使用 Java 8 语法与 `Optional`/`Stream`）
  - Maven：3.6 或更高
  - MongoDB：4.0 或更高（实例、任务、日志、算子注册四个集合）
  - ZooKeeper：3.4 或更高（实例级分布式锁）
  - RabbitMQ：3.7 或更高（任务与结果通道）
  - 浏览器：Chrome / Edge / Firefox 现代版本（前端控制台）
- **可选**
  - Node.js：18+（运行 `frontend/serve.js` 自带的零依赖静态服务器，非编译必需）
  - Python：3.x（可用 `http.server` 替代上述静态服务器）

> 前端是**纯静态页面，无需 npm install、无需构建**，直接用浏览器打开 `index.html` 即可。Node/Python 仅在需要 `http://` 协议访问时才用得上。

## §1 启动中间件

后端启动时会连接 MongoDB、RabbitMQ、ZooKeeper，请先确保三者可用。

### 1.1 MongoDB

```bash
# 本地默认端口 27017
mongod --dbpath /data/mongodb --port 27017
```

集合会自动创建，也可手工预建。注意 `application.yml` 中 `database` 配置为 **`admin`**（系统库），四个业务集合将落在该库中：

```javascript
use admin
db.createCollection("SERVEA_INST")      // 实例
db.createCollection("SERVEA_TASK")      // 任务
db.createCollection("SERVEA_INST_LOG")  // 日志
db.createCollection("REGISTER_INFO")    // 算子注册
```

> 集合与实体的对应关系见 [数据模型与消息模型](04-数据模型与消息模型.md) §9。

### 1.2 ZooKeeper

```bash
# 单机模式，默认端口 2181
zkServer.sh start          # Linux / macOS
zkServer.cmd               # Windows
```

> ZooKeeper 用于实例级锁 `/INST_LOCK_{instId}`（`CreateMode.EPHEMERAL`）。若未启动，`TaskResultConsumer` 抢锁会失败并持续 nack 重排队。

### 1.3 RabbitMQ

```bash
# 默认端口 5672，管理台 15672
rabbitmq-server
```

管理台地址：`http://localhost:15672`（默认 `guest` / `guest`）。

## §2 启动后端

### 第一步：克隆项目

```bash
git clone <仓库地址> service-arrange
cd service-arrange
```

### 第二步：编译

```bash
cd backend
mvn clean install -DskipTests
```

> 多模块结构：根 `pom.xml` 聚合 `backend`，`backend/pom.xml` 再聚合 `engine`（核心引擎）与 `web`（Web 应用）。若只改引擎，可用 `mvn -pl engine install` 快速编译。

### 第三步：核对配置

编辑 `backend/web/src/main/resources/application.yml`。

⚠️ **仓库中的默认配置指向公网 IP `8.129.116.16`**，所有中间件（MongoDB / RabbitMQ / ZooKeeper）都连到该地址。若要在本机运行，需把以下三处改为 `localhost`：

```yaml
# ① MongoDB（L82-89）
spring:
  data:
    mongodb:
      host: localhost        # 原为 8.129.116.16
      port: 27017
      database: admin        # 注意是系统库 admin
      username: admin
      password: 123456

# ② RabbitMQ binder（L36-40）
      binders:
        rabbit_cluster:
          environment:
            spring:
              rabbitmq:
                addresses: localhost:5672   # 原为 8.129.116.16:5672
                username: guest
                password: guest

# ③ ZooKeeper（L95-97）
zk:
  url: localhost:2181      # 原为 8.129.116.16:2181
  session-timeout: 5000
```

另外请留意两点：

- `server.port` 为 `8082`，`server.servlet.context-path` 为 `/servicearrange`，**不要改动**，否则前端与本文档中的示例地址都需同步调整；
- 配置中存在未定义占位符 `${task.shell_task_status}`（L51），以及 L73 的语法错误 `${{task.shell_task_status}`。当前编排逻辑未使用这些项，通常不影响启动。

> Eureka 与 Apollo 已从项目中移除，服务以独立方式运行，无需配置注册中心与配置中心。

逐项含义见 [配置说明](12-配置说明.md)。

### 第四步：启动服务

```bash
cd main
mvn spring-boot:run
```

或在 IDE 中直接运行 `web` 模块的 `ServiceArrangeApplication`。

启动成功后监听 `http://localhost:8082/servicearrange`。

### 第五步：确认 DSL 文件

后端**固定读取** classpath 下的 `hrh_http.json`（见 [项目现状](10-项目现状.md) 缺陷 P1）。该文件位于：

```
backend/web/src/main/resources/hrh_http.json
```

若要验证自定义流程，用前端导出的 DSL 覆盖此文件后重启服务。

## §3 启动前端

前端有两种使用方式。

### 方式一：直接打开（最简单）

用浏览器打开：

```
frontend/index.html
```

> 注意：以 `file://` 协议打开时，向 `http://localhost:8082` 发请求会被浏览器的跨域策略拦截。仅做「编排 + 导出 DSL」时不受影响。

### 方式二：静态服务器（推荐，便于联调）

仓库自带一个零依赖静态服务器 `frontend/serve.js`（仅用 Node 内置模块，无需 `npm install`）：

```bash
cd frontend
node serve.js      # 默认监听 127.0.0.1:5173
```

也可用其他静态服务器替代：

```bash
npx serve .
python -m http.server 5173
```

访问 `http://localhost:5173`，然后在页面右上角「接口设置」中填入后端地址：

```
http://localhost:8082/servicearrange
```

> **必须包含上下文路径 `/servicearrange`**，否则请求会 404。

## §4 验证部署

### 4.1 后端验证

| 验证项 | 方法 | 期望结果 |
| --- | --- | --- |
| 服务已启动 | 观察启动日志出现 `Started ServiceArrangeApplication` | 无异常堆栈 |
| 端口已监听 | `netstat -ano \| findstr :8082` | 显示 LISTENING |
| 接口可达 | `curl "http://localhost:8082/servicearrange/health"` | 返回 `{"code":200,"msg":"success","data":{"status":"UP","mongo":"UP"}}` |
| Mongo 连通 | 同上响应中 `mongo` 为 `UP`（内部执行 `ping`）| 无连接异常 |
| ZK 连通 | 启动日志无 Curator 连接告警 | — |

> 项目**没有**引入 actuator，但提供了自定义 `GET /health`（含 MongoDB 探活）。前端「连通性检测」优先打 `/health`，失败时回退 `registerOperator/findById?id=__ping__`（该接口在 id 不存在时返回 HTTP 200 `null`）。

### 4.2 前端验证

| 验证项 | 操作 | 期望结果 |
| --- | --- | --- |
| 页面加载 | 打开 `index.html` | 顶栏显示「服务编排控制台」，左侧出现节点库 |
| 节点库完整 | 查看左侧 | 基础节点、连线及按样本收录的算子分组 |
| 画布可用 | 拖一个「数据映射」到画布 | 节点出现且被选中，右侧属性面板生成字段 |
| 连线可用 | 从节点右侧圆点拖到目标节点 | 出现灰色连线 |
| 校验可用 | 点「校验流程」 | 弹出校验结果（默认空白模型会提示缺出线，属正常） |
| 示例可用 | 点「加载示例 → 示例 1」 | 画布出现完整 4 节点流程，且校验通过 |
| 导出可用 | 点「导出 DSL」 | 弹出规范 JSON，无 `x`/`y` 字段 |
| 接口连通 | 点「接口设置 → 连通性检测」 | 顶栏变为「已连通」 |

### 4.3 功能测试

1. **编排**：加载「示例 1」，确认 4 个节点与 3 条连线正确渲染，双击节点可看到属性面板。
2. **校验与导出**：点「校验流程」应显示通过；点「导出 DSL」复制 JSON。
3. **后端联调**：把导出的 JSON 通过 `POST /plan/save` 保存为流程模型（`id` 即 `planId`），或直接覆盖 `backend/web/src/main/resources/hrh_http.json` 后重启后端。
4. **调用运行接口**：
   ```bash
   curl -X POST "http://localhost:8082/servicearrange/inst/run/or/getResult/PLAN_2026_001" \
        -H "X-Idempotency-Key: demo-0001" \
        -F "servea_optType=run" \
        -F "servea_sync=false"
   ```
   预期：返回 `{"code":200,"msg":"success","data":{"id":"…","state":"RUNNING","traceId":"…","idempotentHit":false}}`，MongoDB 的 `SERVEA_INST` 出现新实例记录。
5. **观察执行**：`GET /inst/list` 看实例状态，`GET /inst/detail?id={instId}` 看任务与日志，`GET /instlog/list?instId={instId}` 看实例/节点日志。

## §5 常见问题

### 问题：启动报 MongoDB 连接超时

**解决方案**：确认 `mongod` 已启动且端口正确。若使用远程库，检查 `spring.data.mongodb.uri` 中的主机、端口、库名，以及网络与认证配置。

```bash
# 检查端口
netstat -ano | findstr :27017     # Windows
lsof -i :27017                    # Linux / macOS
```

### 问题：启动报 ZooKeeper 连接失败

**解决方案**：项目使用 Curator 连接 ZK 实现实例锁。确认 `zkServer` 已启动，且配置中的 `connect-string` 与实际一致。ZK 未启动不会阻塞应用启动，但实例锁会失效。

### 问题：接口 404

**解决方案**：路径必须包含上下文路径 `/servicearrange`。正确写法：

```
http://localhost:8082/servicearrange/registerOperator/findById?id=xxx
```

前端「接口设置」中的地址也需含该路径。

### 问题：前端请求被 CORS 拦截

**解决方案**：三种处理方式，任选其一：

1. 把 `frontend/` 下文件拷入后端 `backend/web/src/main/resources/static/`，改用同源访问（见 [部署指南](13-部署指南.md) §6）；
2. 后端增加 CORS 配置；
3. 用 `node serve.js` 起静态服务并配置代理（见 §3 方式二）。

### 问题：流程执行到某个节点后不再推进

**排查顺序**：

1. 节点是否被调度：`GET /inst/detail?id={instId}` 查看 `tasks` 中是否出现该 `nodeId`；
2. 节点类型能否解析：画布统一节点 `node_op` 依赖 `data.opType` / `data.cellType`，未命中 `CellTypeMapper` 映射时回退 `node_outer_http`；
3. 执行器与转换器是否齐备：当前 20 个可执行 cellType 均有 `Execute` 与 `TaskInterface` 实现，见 [功能清单](09-功能清单.md) §C；
4. 执行器是否报错：`GET /instlog/list?instId={instId}&nodeId={nodeId}` 查 `ERRO` 级日志；
5. 消息是否被背压丢弃：检查任务的 `lockNackTimes` / `runNackTimes` / `stateNackTimes` 是否触顶（阈值见 [配置说明](12-配置说明.md) §3.3.1）；
6. 实例是否被挂起或取消：`state = SUSPEND` 时流程不推进（需 `POST /inst/resume`），`state = CANCEL` 时后续节点不再调度。

### 问题：端口 8082 被占用

**解决方案**：

```bash
# Windows
netstat -ano | findstr :8082
taskkill /F /PID <PID>

# Linux / macOS
lsof -i :8082
kill -9 <PID>
```

或修改 `application.yml` 中的 `server.port`。

### 问题：Maven 依赖下载失败

**解决方案**：

```bash
mvn dependency:purge-local-repository
mvn clean install -U
```
