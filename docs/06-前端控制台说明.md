## §1 业务流程

整个控制台围绕**「实例 → 编排 → 运行 → 运行记录 → 运行详情」**这一条主线组织，算子注册是支撑编排的前置能力。

```
  ┌──────────────────────────────────────────────────────────────────┐
  │  ⑤ 算子注册（前置能力）                                          │
  │  选择算子包类型（http / sql / shell）→ 填写对应配置 → 保存        │
  │                                    │                             │
  │                                    ▼                             │
  │                          注册后的算子出现在编排页节点库           │
  └──────────────────────────────────────────────────────────────────┘
                                     │
  ┌──────────────────────────────────▼───────────────────────────────┐
  │  ① 实例列表                                                      │
  │  新建实例 ──▶ 点击实例卡片 ──▶ ② 编排页                           │
  │  每张卡片显示：名称 · 最近运行状态 · 节点数 · 运行次数             │
  └──────────────────────────────────┬───────────────────────────────┘
                                     │
  ┌──────────────────────────────────▼───────────────────────────────┐
  │  ② 编排页                                                        │
  │  左：节点库（基础节点 + 已注册算子）                              │
  │  中：画布（拖拽 / 连线 / 决策线 / 循环线 / 补偿线）               │
  │  右：属性面板                                                    │
  │  [保存] 或 [保存并运行]                                          │
  └──────────────────────────────────┬───────────────────────────────┘
                                     │ 运行
  ┌──────────────────────────────────▼───────────────────────────────┐
  │  ③ 运行记录                                                      │
  │  每次运行生成一条记录：序号 · 开始时间 · 耗时 · 状态 · 入参摘要   │
  │  状态：运行中 / 成功 / 失败                                       │
  └──────────────────────────────────┬───────────────────────────────┘
                                     │ 点击某条记录
  ┌──────────────────────────────────▼───────────────────────────────┐
  │  ④ 运行详情                                                      │
  │  Tab1 编排图：只读画布，节点按实际结果染色                        │
  │  Tab2 实例日志：时间轴形式的实例级日志                            │
  │  点击图中任一算子 ──▶ 右侧面板显示该算子的运行日志、入参、出参    │
  └──────────────────────────────────────────────────────────────────┘
```

**六个页面与主导航的关系**：

| 页面 | 进入方式 | 主导航高亮 |
| --- | --- | --- |
| ① 实例列表 | 首页 / 面包屑「实例列表」/ 品牌 logo | 实例列表 |
| ② 编排页 | 实例卡片点「编排」 | 实例列表 |
| ③ 运行记录 | 实例卡片点「运行记录」 | 实例列表 |
| ④ 运行详情 | 运行记录表格点某一行 | 实例列表 |
| ⑤ 算子注册 | 主导航「算子注册」 | 算子注册 |
| ⑥ Schema 工具 | 主导航「Schema 工具」 | Schema 工具 |

> ②③④ 属于「实例」这条主线，因此进入后主导航仍高亮「实例列表」，并通过**面包屑**提示当前所处层级。

## §2 技术选型与模块职责

**纯静态前端，零依赖、零构建**：原生 HTML + CSS + JavaScript（ES5 语法）。直接用浏览器打开 `frontend/index.html` 即可运行。

| 考虑 | 说明 |
| --- | --- |
| 零依赖 | 无需 npm / node_modules / 构建工具，双击即用 |
| 可嵌入 | 可整体拷入后端 `main/src/main/resources/static/` 由 Spring Boot 托管 |
| 易维护 | 按职责拆分为 8 个 JS 模块 |
| 契约清晰 | 导出的 DSL 严格遵循《服务编排 DSL 规范》 |

### 2.1 模块结构

```
frontend/
├── index.html              6 个页面 + 2 个抽屉 + 模态 + Toast
├── css/style.css           全部样式（CSS 变量主题）
└── js/
    ├── schema.js           JSON Schema 构建/解析/类型转换   → SchemaUtil
    ├── nodes.js            节点定义（内置节点 + 动态注入已注册算子）→ NodeDefs
    ├── validator.js        DSL 校验 R1~R9                  → DslValidator
    ├── store.js            数据层（实例/运行记录/算子/日志）+ DSL 序列化 → Store
    ├── api.js              后端接口层（远程优先 + 本地兜底）  → Api
    ├── designer.js         编排画布                        → Designer
    ├── views.js            五个业务页面的视图逻辑           → Instances / Runs / RunDetail / Operators / SchemaTool
    └── app.js              入口、UI 工具、视图路由、运行引擎  → UI / App
```

加载顺序：`schema → nodes → validator → store → api → designer → views → app`。

### 2.2 核心设计：两层数据来源

界面上看到的一切都由 `Store` 提供，`Api` 只负责「是否走远程」的判断：

```
业务代码 ──▶ Api.xxx()  ──┬─ REMOTE 开关打开 ──▶ HTTP 请求后端
                          └─ REMOTE 开关关闭 ──▶ Store（localStorage）
```

当前 `Api.REMOTE` 中 `instance / run / log / operator` 均为 `false`，即全部走本地兜底。后端接口就绪后把对应开关置为 `true` 即可切换，**业务代码无需改动**。

## §3 页面一：实例列表

**实例是本控制台的核心实体**，一个实例即一条完整的编排流程。

### 3.1 界面构成

| 区域 | 内容 |
| --- | --- |
| 页头 | 标题、说明、「＋ 新建实例」按钮 |
| 工具条 | 搜索框（名称 / planId）、状态下拉筛选、总数统计 |
| 卡片网格 | 响应式网格，每张卡片展示一个实例 |

### 3.2 卡片信息

| 元素 | 说明 |
| --- | --- |
| 左侧色条 | 按最近运行状态着色（蓝=运行中 / 绿=成功 / 红=失败 / 灰=未运行） |
| 实例名称 | 创建时填写 |
| 状态徽标 | 运行中（带脉冲动画）/ 成功 / 失败 / 未运行 |
| 描述 | 创建后可补充 |
| 元信息行 | `planId` · 节点数 · 运行次数 · 更新时间 |
| 操作按钮 | 编排 / 运行 / 运行记录 / 删除 |

### 3.3 操作

| 操作 | 行为 |
| --- | --- |
| **新建实例** | 弹出输入框填写名称（支持回车提交）→ 创建后**自动进入编排页** |
| **点击卡片空白处** / 「编排」 | 进入该实例的编排页 |
| **运行** | 校验编排 → 弹出运行入参表单 → 开始运行 → 跳转运行记录 |
| **运行记录** | 进入该实例的运行记录列表 |
| **删除** | 二次确认后删除实例及其全部运行记录 |
| 搜索 / 筛选 | 按名称、`planId`、描述实时过滤；按状态下拉过滤 |

## §4 页面二：编排页

三段式布局：左调色板 / 中画布 / 右属性面板。

```
┌────────────────────────────────────────────────────────────────────┐
│ ← 返回  planId(readonly) │ 导入 导出 │ 校验 保存 保存并运行 │ −100%+⤢✕│
├────────────┬──────────────────────────────────┬────────────────────┤
│ 节点调色板  │                                  │  属性面板           │
│ ┌────────┐ │      ▶ 开始 ──▶ 创建订单 ──▶ ■    │  基础信息           │
│ │搜索…   │ │              │                   │  绑定的算子         │
│ └────────┘ │              └──⟲ 撤销订单       │  节点配置           │
│ ▾ 基础节点 3│                                  │  强组合             │
│ ▾ 连线    4│        （网格画布 + 线型图例）      │  [删除该元素]       │
│ ▾ 内部算子 5│                                  │                     │
│ ▾ HTTP 算子 2                                  │                     │
│ ▾ SQL 算子  1                                  │                     │
│ ▾ Shell 算子1                                  │                     │
│ ▾ 补偿算子 1│                                  │                     │
├────────────┴──────────────────────────────────┴────────────────────┤
│ 状态栏  节点 5 · 连线 4 · 已选中：创建订单                            │
└────────────────────────────────────────────────────────────────────┘
```

### 4.1 节点库的组织

节点库按 **7 大类**分组，其中 **HTTP / SQL / Shell 三类来自「算子注册」的动态数据**：

| 分组 | 来源 | 默认状态 |
| --- | --- | --- |
| 基础节点 | 内置（开始 / 结束 / 全局参数）| 展开 |
| 连线 | 内置（普通 / 决策 / 循环 / 补偿）| **折叠** |
| 内部算子 | 内置（数据映射 / 延时 / 规则转换 / 数据结果 / 补偿数据映射）| 展开 |
| **HTTP 算子** | **动态**：`Store.listOperators('http')` | 有数据时展示 |
| **SQL 算子** | **动态**：`Store.listOperators('sql')` | 有数据时展示 |
| **Shell 算子** | **动态**：`Store.listOperators('shell')` | 有数据时展示 |
| 补偿算子 | 内置（HTTP 补偿）| **折叠** |

> 若尚未注册任何算子，「HTTP / SQL / Shell」三个分组不会出现，并提示去算子注册页添加。

### 4.2 算子节点的表达

拖入画布的算子节点会**绑定具体算子**（`data.opId`），展示其名称与类型摘要：

| 元素 | 内容 |
| --- | --- |
| 图标与颜色 | 按算子包类型着色（HTTP 青 / SQL 紫 / Shell 橙） |
| 名称 | 算子在注册页填写的名称 |
| 副标题 | `类型 · 算子id前6位` |
| 语义徽标 | HTTP 显示请求方法；SQL 显示数据库名；Shell 显示执行环境名 |

若所引用的算子被删除，节点会显示「算子缺失」并以红色提示。

### 4.3 操作手册

| 操作 | 步骤 |
| --- | --- |
| 搜索节点 | 调色板顶部输入关键字（匹配名称 / 类型 / 描述） |
| 折叠分组 | 点分组标题，或底部「全部折叠 / 全部展开」 |
| 新增节点 | 从调色板拖拽到画布 |
| 移动节点 | 直接拖动（坐标随编排一起保存到实例） |
| 连线 | 按住节点右侧圆点拖到目标节点；拖动时**可连接节点高亮** |
| 切换线型 | 选中连线 → 属性面板「线类型」下拉 |
| 编辑属性 | 单击节点或连线，右侧面板按类型动态生成字段 |
| 删除元素 | `Delete` 或属性面板「删除该元素」 |
| 平移 / 缩放画布 | 中键或右键拖动 / `Ctrl+滚轮` / `＋ − ⤢` |
| 加入补偿组 | 属性面板「加入补偿组」→ 选择或新建 |

### 4.4 工具栏

| 按钮 | 行为 |
| --- | --- |
| **← 返回** | 保存当前编排并回到实例列表 |
| **导入** | 粘贴 DSL JSON 覆盖画布 |
| **导出** | 按规范导出 DSL（剔除视图坐标、补全 `name`/`ports`、反向填充 `groups.nodes`），可复制 |
| **校验** | 按 R1~R9 规则校验，错误阻断运行，提示不阻断 |
| **保存** | 保存编排回实例并返回实例列表 |
| **保存并运行** | 先校验（不通过则拦截）→ 保存 → 弹出运行入参 → 开始运行 |

## §5 页面三：运行记录

### 5.1 界面构成

## §6 页面四：运行详情

展示**某一次运行**的完整过程。左侧为编排图与实例日志，右侧为算子级日志面板。

### 6.1 页头信息

| 元素 | 内容 |
| --- | --- |
| 返回按钮 | 回到该实例的运行记录 |
| 序号 | `#1`、`#2`… |
| 开始时间 | 精确到秒 |
| 状态徽标 | 与运行记录一致 |
| 统计 | 共 N 节点 · 成功 N · 失败 N · 跳过 N · 耗时 N ms |

### 6.2 Tab1：编排图

**只读画布**，节点按该次运行的**实际执行结果染色**：

| 节点外观 | 含义 |
| --- | --- |
| 绿色边框 + 浅绿底 | 执行成功 |
| 红色边框 + 浅红底 | 执行失败 |
| 灰色 + 半透明 | 已跳过（失败后续 / 父节点跳过） |
| 蓝色边框 + 浅蓝底 | 正在执行 |
| 白色 | 未执行 |

节点卡片额外显示**执行状态徽标**与**耗时**。图下方有颜色图例，右侧提示「点击算子查看其运行日志 →」。

| 操作 | 说明 |
| --- | --- |
| 点击节点 | 右侧面板加载该算子的运行日志 |
| 平移 | 中键 / 右键拖动 |
| 缩放 | `Ctrl + 滚轮` |

### 6.3 Tab2：实例日志

时间轴形式的**实例级日志**，深色终端风格：

| 列 | 内容 |
| --- | --- |
| 时间 | `HH:mm:ss` |
| 级别 | `INFO` 蓝 / `WARN` 黄 / `ERRO` 红 |
| 节点名 | 产生该日志的节点 |
| 内容 | 日志正文 |

支持按级别筛选与「自动滚动」开关（默认开，自动滚到底部）。

### 6.4 右侧：算子运行日志面板

点击编排图中任一算子后，该面板展示四级信息：

| 区块 | 内容 |
| --- | --- |
| 统计 | 状态 / 耗时 / 日志条数 |
| **入参** | 该算子本次执行的入参（JSON，深色代码块） |
| **出参** | 该算子本次执行的出参（JSON，深色代码块） |
| **算子日志** | 该算子专属的日志列表（时间 + 级别 + 内容） |
| **异常信息** | 仅失败时展示，红色代码块 |

> 这实现了「实例日志」与「算子日志」的**两级日志体系**：实例日志看全局流水，算子日志看单点细节。

## §7 页面五：算子注册

注册后的算子会**自动出现在编排页的节点库中**。

### 7.1 列表界面

| 区域 | 内容 |
| --- | --- |
| 页头 | 说明 +「＋ 新建算子」 |
| 工具条 | 搜索框、类型分段控件（全部 / HTTP / SQL / Shell）、总数 |
| 卡片网格 | 每张卡片展示一个算子 |

**算子卡片**：左侧色条按类型着色；显示图标、名称、类型、描述、**配置预览**（HTTP 显示 `METHOD url`，SQL 显示数据库与首行 SQL，Shell 显示环境与首行脚本）；底部为编辑 / 查看配置 / 删除。

### 7.2 编辑抽屉：按算子包类型动态切换

新建算子时必须**先选择算子包类型**，表单随之切换：

#### HTTP 类型

| 字段 | 说明 |
| --- | --- |
| 请求方法 | GET / POST / PUT / DELETE / PATCH |
| 内容类型 | `application/json` 等 4 种 |
| 请求地址 | 支持 `{id}` 占位 |
| Headers | 键值对列表，可增删 |
| Query 参数 | 键值对列表，可增删 |
| Body | 多行文本 |

#### SQL 类型

| 字段 | 说明 |
| --- | --- |
| 选择数据库 | 下拉：`mysql-main` / `mysql-report` / `pg-order` / `oracle-legacy` |
| SQL 语句 | 大号等宽代码编辑框，支持 `#{参数名}` 占位 |

#### Shell 类型

| 字段 | 说明 |
| --- | --- |
| 执行环境 | 下拉：`linux-prod-01` / `linux-prod-02` / `linux-test-01` / 本机 |
| 超时(ms) | 数字 |
| 脚本内容 | 大号等宽代码编辑框，支持 `${参数名}` 占位 |

> 编辑已有算子时**类型不可修改**，避免已编排节点的语义漂移。

### 7.3 校验规则

| 类型 | 必填校验 |
| --- | --- |
| 通用 | 算子名称 |
| HTTP | 请求地址 |
| SQL | 数据库 + SQL 语句 |
| Shell | 执行环境 + 脚本内容 |

## §8 页面六：Schema 工具

| 列 | 说明 |
| --- | --- |

## §9 数据模型

前端在 localStorage 中维护四类数据（key 前缀 `sa.`）：

| key | 内容 |
| --- | --- |
| `sa.instances` | `{ [instId]: Instance }` |
| `sa.runs` | `{ [instId]: RunRecord[] }` |
| `sa.operators` | `{ [opId]: Operator }` |
| `sa.settings` | `{ apiBase }` |

### 9.1 Instance（实例）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 实例 id |
| `name` | string | 实例名称 |
| `description` | string | 描述 |
| `planId` | string | 流程标识（自动生成，如 `PLAN_A1B2C3D4`）|
| `cells` | array | 编排节点与连线（与 DSL 规范一致）|
| `groups` | array | 强组合（补偿组）|
| `lastRunState` | string | 最近一次运行状态 |
| `runCount` | number | 运行次数 |
| `createTime` / `updateTime` | number | 时间戳 |

### 9.2 RunRecord（运行记录）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 运行记录 id |
| `instId` | string | 所属实例 |
| `seq` | number | 运行序号（从 1 递增）|
| `state` | string | `RUNNING` / `SUCCESS` / `FAIL` |
| `startTime` / `endTime` | string | ISO 时间 |
| `duration` | number | 总耗时（ms）|
| `inputs` | object | 本次运行入参 |
| `cells` / `groups` | array | **运行时的编排快照**（保证历史可回溯）|
| `nodeStates` | object | `{ [cellId]: { state, duration, inputs, outputs, error } }` |
| `logs` | array | 实例级日志 |
| `nodeLogs` | object | `{ [cellId]: Log[] }` 算子级日志 |

### 9.3 Operator（算子）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 算子 id |
| `opType` | string | `http` / `sql` / `shell` |
| `name` | string | 算子名称 |
| `description` | string | 描述 |
| HTTP 专属 | — | `url` / `method` / `contentType` / `headers[]` / `query[]` / `body` |
| SQL 专属 | — | `database` / `sql` |
| Shell 专属 | — | `env` / `script` / `timeout` |

## §10 与后端的接口契约

### 10.1 已实现并已对接

| 接口 | 用途 | 状态 |
| --- | --- | --- |
| `POST /inst/run/or/getResult/{planId}` | 运行实例 / 查询结果 | ✅ 已封装（`Api.runOrGetResult`），编排页「运行」当前走本地模拟，后端就绪后可切换 |
| `POST /registerOperator/save` | 保存算子注册 | ✅ 已封装（`Api.saveRegisterInfo`）|
| `POST /registerOperator/delete` | 批量删除 | ✅ 已封装（`Api.deleteRegisterInfo`）|
| `GET /registerOperator/findById` | 按 id 查询 | ✅ 已封装，同时用作**连通性探针** |

### 10.2 前端已预留、后端待实现

以下接口已在 `api.js` 中按建议契约写好方法，当前由本地 `Store` 兜底。后端实现后，把 `Api.REMOTE` 中对应开关置为 `true` 即可切换。

| 建议路径 | 方法 | 用途 | REMOTE 开关 |
| --- | --- | --- | --- |
| `/instance/list` | GET | 实例列表 | `Api.REMOTE.instance` |
| `/instance/findById?id=` | GET | 实例详情 | 同上 |
| `/instance/save` | POST | 保存实例（含编排）| 同上 |
| `/instance/delete` | POST | 批量删除实例 | 同上 |
| `/instance/run` | POST | 运行实例，返回 `runId` | `Api.REMOTE.run` |
| `/run/list?instId=` | GET | 运行记录列表 | 同上 |
| `/run/findById?id=` | GET | 运行记录详情（含编排快照与节点状态）| 同上 |
| `/run/delete` | POST | 删除运行记录 | 同上 |
| `/log/list?runId=` | GET | 实例级日志 | `Api.REMOTE.log` |
| `/log/nodeLogs?runId=&nodeId=` | GET | 算子级日志 | 同上 |
| `/operator/list?opType=` | GET | 算子列表 | `Api.REMOTE.operator` |
| `/operator/findById?id=` | GET | 算子详情 | 同上 |
| `/operator/save` | POST | 保存算子 | 同上 |
| `/operator/delete` | POST | 批量删除算子 | 同上 |

> 后端现有接口的字段模型（`serviceName` / `serviceUrl` / `reqBodyData` 等）与本前端的算子模型（`name` / `url` / `sql` / `script` 等）**不一致**，因此 `REMOTE.operator` 暂为 `false`。切换前需先对齐字段，或在 `api.js` 中增加一层字段映射。

### 10.3 接口设置

右上角「⚙ 接口设置」可配置后端基础地址：

```
http://localhost:8082/servicearrange
```

需包含上下文路径 `/servicearrange`。顶栏状态灯显示连通结果（**后端不可达时本地功能仍可完整使用**）。

## §11 部署方式

### 方式一：直接打开（最简单）

浏览器打开 `frontend/index.html`。仅做编排与导出时不受跨域限制。

```powershell
cd frontend
npx serve .
# 或
python -m http.server 5173
```

### 方式二：由后端托管（无跨域）

把文件拷入后端资源目录：

```bash
cp -r frontend/* backend/web/src/main/resources/static/
```

访问 `http://localhost:8082/servicearrange/index.html`。

### 方式三：Nginx 托管 + 反向代理

见 [部署指南](13-部署指南.md) §6.1。

## §12 扩展指南

| 需求 | 修改位置 |
| --- | --- |
| 新增内置节点类型 | `js/nodes.js` 的 `NODES` 数组追加一项（含 `cellType` / `name` / `cat` / `kind` / `icon` / `defaultData` / `schema`）|
| 新增算子包类型（如 `mq`）| ① `js/store.js` 的 `OP_TYPES` 与 `newOperator()`；② `js/nodes.js` 的 `CATS` 与 `byCategory()` 的 `['http','sql','shell']` 数组；③ `index.html` 中 `#opType2` 下拉与对应表单区；④ `js/views.js` 的 `switchForm()` / `save()` |
| 新增分类 | `js/nodes.js` 的 `CATS` 增加一项 |
| 节点徽标 | `js/designer.js` 的 `nodePresentation()` |
| 新增校验规则 | `js/validator.js` 的 `validate()` |
| 新增后端接口 | `js/api.js` 追加方法（含 REMOTE 开关），在 `js/views.js` 中调用 |
| 调整主题色 | `css/style.css` 顶部 `:root` 变量 |
| 调整运行逻辑 | `js/app.js` 的 `App.startRun()`（当前为前端模拟，替换为 `Api.instance.run` 即可接后端）|
| 新增页面 | `index.html` 加 `<main class="view" id="view-xxx">`；`js/app.js` 的 `App.show()` 增加分支与导航项 |

**内置节点定义的完整字段**：

```javascript
{
  cellType: 'node_inner_xxx',   // 必填，与后端 CellType 一致
  name: '显示名',
  cat: 'inner',                 // 分类 key
  kind: 'node',                 // 'node' | 'edge'
  icon: '×',                    // 单字符图标
  desc: '一句话说明',
  fixed: false,                 // 可选，true 表示画布唯一
  defaultData: function () { return {}; },
  schema: [ /* 属性面板字段 */ ]
}
```

> 算子节点统一使用 `cellType = node_op`，具体算子通过 `data.opId` 绑定，**无需为每个算子新增 `cellType`**。
