## §4 调度状态机

### 4.1 实例状态

```
        ┌──────────┐
        │  (创建)  │
        └────┬─────┘
             │ run
             ▼
        ┌──────────┐   全部节点完成    ┌──────────┐
        │ RUNNING  │─────────────────▶│ SUCCESS  │
        └────┬─────┘                  └──────────┘
             │ 任一节点 FAIL
             ├───────────────────────▶┌──────────┐
             │                        │   FAIL   │
             │ 人工挂起                └──────────┘
             ▼
        ┌──────────┐   恢复
        │ SUSPEND  │──────────▶ RUNNING
        └──────────┘
```

### 4.2 任务状态

```
   (创建) ──▶ RUNNING ──┬──▶ SUCCESS ──▶ 推进下一批节点
                        ├──▶ FAIL    ──▶ 有补偿线？→ 补偿任务 : 实例 FAIL
                        └──▶ SKIP    ──▶ 视为已处理，继续推进
```

`SKIP` 的三种产生场景：

| 场景 | 说明 |
| --- | --- |
| 父节点全部 SKIP | 子节点也被跳过（`TaskResultConsumer` L388-393）|
| 决策线不通过 | 目标节点被置 SKIP，流程改走其他分支（L396-415）|
| 循环区间重置 | 区间内节点在每轮循环开始时被移出状态集合（L215-222）|

## §7 后续迭代建议

按优先级排列：

1. **修复决策线与 whileDo 的 Bug**（高优先，否则条件分支/循环能力不可用）；
2. ✅ **已完成**：`Plan` 模型管理（实体 + `SERVEA_PLAN` 集合 + CRUD / 发布接口），`planId` 已真正关联 DSL；
3. ✅ **已完成**：脚本类算子（Shell / Jar / Python）与执行器；
4. ✅ **已完成**：Dubbo / WebService 算子及其补偿算子；
5. **把 `TaskProductor` 改为真正的 MQ 投递**，启用 `MqChannelProcessor` 中已定义的通道，支持多实例水平扩容；
