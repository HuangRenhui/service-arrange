## §2 server 配置

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| `server.port` | `8082` | HTTP 监听端口 |
| `server.servlet.context-path` | `/servicearrange` | 应用上下文路径 |

**对外完整地址**：`http://{host}:8082/servicearrange`

调用任何接口都必须带上上下文路径，否则 404。示例：

```
http://localhost:8082/servicearrange/registerOperator/findById?id=xxx
```

> 前端「接口设置」中的后端基础地址也要写成 `http://localhost:8082/servicearrange`。

> 集合与实体的对应关系见 [数据模型与消息模型](04-数据模型与消息模型.md) §8。

### 3.3 RabbitMQ（Spring Cloud Stream）

本项目通过 **Spring Cloud Stream** 使用 RabbitMQ，而非直接使用 `spring.rabbitmq.*`。因此**不存在** `spring.rabbitmq.host` 这样的配置，连接信息写在 binder 的 environment 中。

**Binder 定义**

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| `spring.cloud.stream.binders.rabbit_cluster.type` | `rabbit` | Binder 类型 |
| `...rabbit_cluster.environment.spring.rabbitmq.addresses` | `8.129.116.16:5672` | MQ 地址 |
| `...rabbitmq.username` | `guest` | 账号 |
| `...rabbitmq.password` | `guest` | 密码 |

**Bindings 定义**（4 个通道，全部绑定到同一个交换器）

| 通道名 | 类型 | destination | group | content-type |
| --- | --- | --- | --- | --- |
| `output_channel` | 生产者 | `${spring.application.name}-exchange-point` | — | `application/json` |
| `task_run_input_channel` | 消费者 | 同上 | `${task.run_queue_name}` = `/task/run` | `application/json` |
| `task_result_input_channel` | 消费者 | 同上 | `${task.result_queue_name}` = `/task/result` | `application/json` |
| `shell_task_status_channel` | 消费者 | 同上 | `${task.shell_task_status}`（未定义） | `application/json` |

**Rabbit 专属配置**

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| `...rabbit.bindings.output_channel.producer.routing-key-expression` | `headers.receiveSign` | 用消息头的 `receiveSign` 作为路由键 |
| `...task_run_input_channel.consumer.acknowledge-mode` | `manual` | 手工 ACK（对应 `TaskRunConsumer` 中的 `basicAck`/`basicNack`）|
| `...task_result_input_channel.consumer.acknowledge-mode` | `manual` | 同上（对应 `TaskResultConsumer`）|
| `...task_run_input_channel.consumer.concurrency` | `1` | 消费并发数 |
| `...task_result_input_channel.consumer.concurrency` | `1` | 消费并发数 |

> ⚠️ **两处配置问题**：
> 1. `spring.application.name` 与 `spring.cloud.stream` 同级，所以 `destination: ${spring.application.name}-exchange-point` 能正确解析为 `servicearrange-exchange-point`；
> 2. `shell_task_status_channel` 的 `group` 引用了 `${task.shell_task_status}`，但 `task` 节点下**没有定义该属性**；同时 L73 的 `binding-routing-key` 写成了 `${{task.shell_task_status}`（多了一个 `{`）。该通道当前无实际使用方，因此未暴露问题。
>
> 另需注意：`TaskProductor` 的 `sendTaskRun` / `sendTaskResult` 当前是**本地直调**，并未真正走这些通道，详见 [项目现状](10-项目现状.md) 缺陷 P2。

## §4 自定义配置

以下配置项由业务代码通过 `@Value` 注入，是**必须存在**的属性。

| 配置项 | 值（当前） | 注入位置 | 说明 |
| --- | --- | --- | --- |
| `zk.url` | `8.129.116.16:2181` | `ZookeeperConfig` | ZooKeeper 连接地址 |
| `zk.session-timeout` | `5000` | `ZookeeperConfig` | 会话超时（毫秒）|
| `task.run_queue_name` | `/task/run` | `TaskProductor` `@Value` | 任务执行队列名 |
| `task.result_queue_name` | `/task/result` | `TaskProductor` `@Value` | 任务结果队列名 |

**ZooKeeper 用途说明**：实例级分布式锁，路径为 `/INST_LOCK_{instId}`，节点类型 `CreateMode.EPHEMERAL`。同一实例的任务结果消息严格串行处理，避免状态集合并发推进。会话断开时临时节点自动删除，天然防死锁。详见 [数据模型与消息模型](04-数据模型与消息模型.md) §10。

**队列名用途说明**：`task.run_queue_name` / `task.result_queue_name` 同时被用作：

1. `TaskProductor` 中的 `@Value` 注入；
2. `application.yml` 中两个 input channel 的 `group` 与 `binding-routing-key`。

两处必须保持一致，否则消息路由错乱。

### 5.2 Eureka 服务注册

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| `eureka.client.service-url.defaultZone` | `${eureka-url}` | ⚠️ **该属性未定义** |

## §6 生产环境整改建议

按优先级排列。

| 优先级 | 项 | 现状 | 建议 |
| --- | --- | --- | --- |
| **高** | 明文密码 | MongoDB 密码 `123456`、MQ 密码 `guest` 硬编码在 YAML | 改为环境变量：`${MONGO_PASSWORD}` / `${MQ_PASSWORD}` |
| **高** | 公网地址 | 所有中间件指向 `8.129.116.16` | 改为内网地址或服务名（容器环境下用 K8s Service）|
| **高** | 数据库名 | 使用 `admin` 系统库 | 改用独立业务库，如 `servicearrange` |
| **中** | 环境隔离 | 只有一份 `application.yml` | 拆分为 `application-dev.yml` / `application-prod.yml`，用 `spring.profiles.active` 切换 |
| **中** | 未定义占位符 | `${eureka-url}` / `${task.shell_task_status}` 未定义 | 补齐定义或删除无人使用的配置 |
| **中** | 语法错误 | L73 `${{task.shell_task_status}` 多一个 `{` | 修正为 `${task.shell_task_status}` |
| **低** | 消费并发 | 均为 `1` | 压测后按需上调 |
| **低** | Apollo | 声明未启用 | 如无使用计划，移除依赖与配置以降低复杂度 |
| **低** | 密码策略 | `123456` | 使用高强度密码并定期轮换 |

### 推荐的生产配置模板（示例，非当前生效）

```yaml
server:
  port: ${SERVER_PORT:8082}
  servlet:
    context-path: /servicearrange

spring:
  application:
    name: servicearrange
  data:
    mongodb:
      host: ${MONGO_HOST}
      port: ${MONGO_PORT:27017}
      database: servicearrange
      username: ${MONGO_USERNAME}
      password: ${MONGO_PASSWORD}
  cloud:
    stream:
      binders:
        rabbit_cluster:
          type: rabbit
          environment:
            spring:
              rabbitmq:
                addresses: ${MQ_ADDRESSES}
                username: ${MQ_USERNAME}
                password: ${MQ_PASSWORD}

zk:
  url: ${ZK_URL}
  session-timeout: 5000

task:
  run_queue_name: /task/run
  result_queue_name: /task/result
```

启动时通过环境变量注入敏感信息：

```bash
export MONGO_HOST=10.0.0.11 MONGO_USERNAME=app MONGO_PASSWORD='***'
export MQ_ADDRESSES=10.0.0.12:5672 MQ_USERNAME=app MQ_PASSWORD='***'
export ZK_URL=10.0.0.13:2181
java -jar service-arrange.jar
```
