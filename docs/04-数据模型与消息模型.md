## §1 数据模型总览

```
             ┌───────────────┐
             │     Plan      │  流程模型：DSL + 生命周期（DRAFT / PUBLISHED / DISABLED）
             │  SERVEA_PLAN  │
             └──────┬────────┘
                    │ 1 : N（运行按 planId 取 dsl，并快照 version / env 到实例）
             ┌──────▼────────┐
             │     Inst      │  一次流程运行的完整上下文（内存图 + 状态集合 + 出参）
             │  SERVEA_INST  │
             └──────┬────────┘
                    │ 1 : N
             ┌──────▼────────┐
             │     Task      │  某节点在某循环次数下的一次执行记录
             │  SERVEA_TASK  │
             └──────┬────────┘
                    │ 1 : N
             ┌──────▼────────┐
             │    InstLog    │  实例/节点级日志
             │ SERVEA_INST_LOG│
             └───────────────┘

             ┌──────────────────────┐
             │  RegisterInfoEntity  │  算子注册（外部 API 元信息）
             │    REGISTER_INFO     │
             └──────────────────────┘
```

## §4 `Task`（任务）

一个节点在某个循环次数下的一次执行记录。集合名 `SERVEA_TASK`。

### 4.1 状态常量

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `STATE_WAITE` | `WAITE` | 等待（`convert` 后的初始状态）|
| `STATE_RUNNING` | `RUNNING` | 执行中 |
| `STATE_SUCCESS` | `SUCCESS` | 成功 |
| `STATE_SKIP` | `SKIP` | 跳过（父节点跳过 / 决策不通过）|
| `STATE_FAIL` | `FAIL` | 失败 |

### 4.2 字段（真实定义 + `@Field` 映射）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `instId` | `String` | 所属实例 |
| `planId` | `String` | 所属流程（模型）id |
| `planName` | `String` | 模型名称 |
| `nodeId` | `String` | 节点（Cell）id |
| `nodeName` | `String` | 节点名，为空时回退 `cellType_id` |
| `state` | `String` | 任务状态 |
| `type` | `String` | 任务类型 = `cellType`（Execute Bean 名）|
| `debug` | `Boolean` | 是否调试运行，默认 `false` |
| `inputs` | `String` | 节点入参 |
| `rollbackState` | `String` | 回滚状态 |
| `outputs` | `Task.Result` | 节点出参 |
| `retryRules` | `Task.RetryRules` | 重试规则 |
| `stateNackTimes` | `Integer` | 结果处理阶段 nack 次数（≥5 强制 ack），默认 `0` |
| `runNackTimes` | `Integer` | 执行阶段 nack 次数（≥5 强制 ack），默认 `0` |
| `lockNackTimes` | `Integer` | 抢实例锁失败重排队次数（≥10 强制 ack），默认 `0` |
| `nextRetryTime` | `Date` | 下次可重投时间，抢锁退避时写入（`now + backoffMs(nackTimes)`）|
| `startDate` | `Date` | 总开始时间 |
| `endDate` | `Date` | 总结束时间 |
| `executorStartDate` | `Date` | 执行器开始时间 |
| `executorEndDate` | `Date` | 执行器结束时间 |
| `loopTimes` | `String` | 循环标识，格式 `循环线id\|次数`，非循环节点为 `"0"` |
| `errorClass` | `String` | 错误分类 `SUCCESS` / `RETRYABLE` / `FATAL`，由 `ErrorClassifier` 依据 `task.error-mapping.*` 产出；为空表示未分类（旧数据，消费端按可重试处理）|
| `errorCode` | `String` | 归一化错误码：HTTP 状态码、业务码、SQLState、脚本退出码或 SOAP Fault 码 |
| `errorMessage` | `String` | 归一化错误描述，便于排障与日志检索 |

### 4.3 内嵌结构（真实定义）

**`Task.Result`**（节点返回值）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `contentType` | `String` | 出参类型 |
| `jsonSchema` | `String` | 出参类型映射关系 ⚠️ 非 `body` |
| `value` | `String` | 出参值 ⚠️ 为 **String**，非对象 |
| `headerParams` | `Map<String,String>` | 出参头信息 |

**`Task.RetryRules`**（重试规则）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `times` | `Integer` | 重试次数 |
| `doneTimes` | `Integer` | 已重试次数，默认 `0` ⚠️ 非 `interval` |
| `delaySecondTimes` | `Long` | 重试间隔（单位：秒）⚠️ 非 `condition`；实际等待被 `task.orchestration.retry-delay-max-ms`（默认 3000ms）封顶 |
| `timeoutMs` | `Long` | 单任务超时（毫秒）；为空时回退全局 `task.orchestration.task-timeout-ms`（默认 60000）|

> 注意：`RetryRules` 中**没有** `condition` 字段，重试触发条件当前由执行器自行判断（`HttpTaskExecutor` 中通过 `error` 关键字匹配）。

### 4.4 关键索引（按使用方式推导）

| 索引 | 用途 |
| --- | --- |
| `{ instId, nodeId }` | `findAllByInstIdAndNodeIdIn`（决策求值取节点输出）|
| `{ instId, nodeId, loopTimes }` | `findByInstIdAndNodeIdAndLoopTimes`、`deleteByInstIdAndNodeIdAndLoopTimes` |

## §5 `InstLog`（日志）

集合名 `SERVEA_INST_LOG`。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 字段 | 类型 | `@Field` | 说明 |
| --- | --- | --- | --- |
| `instId` | `String` | `instId` | 实例 id |
| `planId` | `String` | `planId` | 流程 id |
| `nodeId` | `String` | `nodeId` | 节点 id |
| `taskId` | `String` | `taskId` | 任务 id |
| `level` | `String` | `level` | 日志级别，默认 `INFO` |
| `message` | `String` | `message` | 日志内容 ⚠️ 字段名为 **`message`**，不是 `content` |

日志级别常量（注意源码拼写）：

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `LEVEL_INFO` | `"INFO"` | 信息 |
| `LEVEL_WARN` | `"WARN"` | 警告 |
| `LEVEL_ERRO` | `"ERRO"` | 错误 ⚠️ 常量名与值均**缺少 `R`**（应为 `LEVEL_ERROR` / `"ERROR"`）|

**两个构造函数**（源码实际签名）：

```java
// 5 参：级别 + 内容
InstLog(String instId, String planId, String nodeId, String taskId, String level, String message)

// 5 参（重载）：只传级别，message 为 null
InstLog(String instId, String planId, String nodeId, String taskId, String level)

// 无参构造：会自动设置 createDate
InstLog()
```

实际用法示例：

```java
// 6 参 —— 级别 + 内容（推荐，信息最全）
instLogDao.save(new InstLog(task.getInstId(), task.getPlanId(), task.getNodeId(), task.getId(),
        InstLog.LEVEL_ERRO, "下标越界！" + e.getMessage()));

// 5 参 —— 仅级别（message 为 null，多见于 TaskProductor 的占位日志）
instLogDao.save(new InstLog(task.getInstId(), task.getPlanId(), task.getNodeId(), task.getId(),
        InstLog.LEVEL_INFO));
```

> ⚠️ **注意**：源码中**不存在**「5 参 = 内容」的构造。若要设置日志内容，必须使用 6 参形式并显式传级别。

## §7 `Plan`（流程模型）

流程模型（可发布、可运行的编排定义）。`@Document` 集合名 **`SERVEA_PLAN`**。

### 7.1 字段（真实定义 + `@Field` 映射）

| 字段 | 类型 | `@Field` | 说明 |
| --- | --- | --- | --- |
| `name` | `String` | `name` | 模型名称 |
| `dsl` | `String` | `dsl` | DSL JSON 字符串（运行时的唯一来源）|
| `remark` | `String` | `remark` | 备注 |
| `version` | `Integer` | `version` | 版本号，默认 `1`；发布与「更新未显式传版本」时自增 |
| `status` | `String` | `status` | 生命周期状态，默认 `DRAFT` |
| `env` | `String` | `env` | 环境标识，运行实例时快照进 `Inst.env` |
| `owner` | `String` | `owner` | 负责人 |
| `defaultTimeoutMs` | `Long` | `defaultTimeoutMs` | 模型级默认任务超时（节点 `RetryRules.timeoutMs` 优先）|
| `id` / `createDate` / `modifyDate` | — | — | 继承自 `BaseEntity` |

### 7.2 生命周期常量

| 常量 | 值 | 说明 |
| --- | --- | --- |
| `STATUS_DRAFT` | `DRAFT` | 草稿；`task.orchestration.require-published = true` 时不可运行 |
| `STATUS_PUBLISHED` | `PUBLISHED` | 已发布；门禁开启时唯一可运行状态 |
| `STATUS_DISABLED` | `DISABLED` | 已停用；**任何情况下都不可运行** |

### 7.3 与实例的关系

| 关系 | 说明 |
| --- | --- |
| 运行入口 | `InstController.loadDsl(planId)` 按 id 读取 `Plan.dsl` |
| 版本快照 | 运行时把 `Plan.version` / `Plan.env` 写入 `Inst.planVersion` / `Inst.env` |
| 快照隔离 | 实例落库时已解析进 `Inst.nodeMap`，后续修改 / 发布 Plan 不影响在跑实例 |

> 接口见 [REST接口说明](05-REST接口说明.md) §3；发布门禁的取值见 [配置说明](12-配置说明.md) §3.3.1。

## §10 消息模型

### 10.1 通道定义（`MqChannelProcessor`）

Java 侧**只定义了 3 个**通道常量：

| 常量 | 通道名 | 方向 | 绑定方法 | 用途 |
| --- | --- | --- | --- | --- |
| `OUTPUT` | `output_channel` | `@Output` | `taskProductor()` | 通用产出通道 |
| `TASK_RUN_INPUT` | `task_run_input_channel` | `@Input` | `taskRunConsumer()` | 任务执行入队 |
| `TASK_RESULT_INPUT` | `task_result_input_channel` | `@Input` | `taskResultConsumer()` | 任务结果回传 |

```java
public interface MqChannelProcessor {
    String OUTPUT = "output_channel";
    String TASK_RUN_INPUT = "task_run_input_channel";
    String TASK_RESULT_INPUT = "task_result_input_channel";

    @Input(TASK_RESULT_INPUT)  SubscribableChannel taskResultConsumer();
    @Input(TASK_RUN_INPUT)     SubscribableChannel taskRunConsumer();
    @Output(OUTPUT)            MessageChannel taskProductor();
}
```

> **第 4 个通道**：`application.yml` 中额外配置了 `shell_task_status_channel`（消费者），但它**没有对应的 Java 常量与绑定方法**，且其 `group` 引用了未定义的 `${task.shell_task_status}`、`binding-routing-key` 存在 `${{` 语法错误。该通道当前无实际使用方。详见 [配置说明](12-配置说明.md) §3.3。

### 10.2 `Task4MQ`（任务消息体）

轻量消息，只带定位信息，消费端再查库：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `String` | 任务 id |
| `type` | `String` | 任务类型（= cellType，用于选 Execute Bean）|

```json
{ "id": "6650f3...", "type": "node_outer_http" }
```

### 10.3 消息流转

```
TaskProductor.sendTaskRun(task)
   └─▶ Task4MQ{id,type} ──▶ task_run_input_channel ──▶ TaskRunConsumer
                                                        └─ getBean(type).run(taskId)

TaskRunConsumer 执行完（Execute 内部调用）
   └─▶ TaskProductor.sendTaskResult(task)
          └─▶ task_result_input_channel ──▶ TaskResultConsumer
                                              └─ 加 ZK 锁 → 编排下一批节点
```

### 10.4 ACK 策略

| 场景 | 动作 | 方法 |
| --- | --- | --- |
| 正常完成 | `basicAck` | `TaskProductor.ackTask(deliveryTag, channel, msg)` |
| 需重试 | `basicNack(requeue=true)` | `TaskProductor.nAckTask(deliveryTag, channel, msg)` |
| 拿不到实例锁 | 退避后 `nack` + 删 ZK 节点 | `nAckLockTask(taskId, instId, deliveryTag, channel, msg)`；超 `lock-nack-max-times` 改为 `ack` 丢弃 |
| 完成且持锁 | `ack` + 删 ZK 节点 | `ackTask(instId, deliveryTag, channel, msg)` |
| 重试超限 | 强制 `ack` | 直接 ack，防止毒消息 |

> 背压相关字段：`Task.lockNackTimes`（重排队次数）、`Task.nextRetryTime`（下次可重投时间）；
> 阈值与退避参数见 [配置说明](12-配置说明.md) §3.3.1。

## §11 分布式锁（ZooKeeper）

| 项 | 值 |
| --- | --- |
| 实例锁路径 | `Inst.ZK_LOCK_PREFIX + instId` = `/INST_LOCK_{instId}` |
| 准入锁路径 | `Inst.ZK_PLAN_LOCK_PREFIX + planId` = `/PLAN_RUNNING_{planId}`（节点数据为持有者 `instId`）|
| 模式 | `CreateMode.EPHEMERAL` |
| 客户端 | Apache Curator `CuratorFramework` |
| 持有者 | 实例锁：`MqTaskResultListener`（结果消费抢锁，抢不到 `nack` 重排队）<br>准入锁：`InstController.acquireRunLock`（入口抢锁，抢不到 400）|
| 释放 | 实例锁：`TaskProductor` 执行完 / 结果落库后释放<br>准入锁：`/inst/cancel`、`/inst/delete` 显式释放；属主终态后由下次抢占自愈清理；会话结束自动消失 |

**加锁时机**：`TaskResultConsumer.listenInstTaskResult`（L82-83）——处理结果消息前先抢锁。
**释放时机**：`TaskProductor.ackTask(instId,...)` / `nAckTask(instId,...)`（L53-69）。

语义：**同一实例的结果消息严格串行处理**，防止「同一实例多个节点结果并发推进」导致状态集合竞争。会话断开时临时节点自动删除，天然避免死锁。
